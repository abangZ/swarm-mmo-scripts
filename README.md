# Swarm MMO 助手

React + TypeScript + esbuild 工程，打包为一个独立的 Tampermonkey 油猴脚本，无运行时 CDN 依赖。

## 开发与构建

需要 Node.js 22+ 和 pnpm 10.34.5（版本已在 `packageManager` 中固定）。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm typecheck
pnpm dev      # 监听源码并重新打包；配合本地加载脚本，刷新游戏即可加载更新
```

输出：`dist/swarm-mmo.user.js`。在 Tampermonkey 中新建脚本，将此文件完整内容粘贴并保存，随后刷新游戏 `/play` 页面。后续重新构建后，需要重新替换已安装脚本的内容。脚本要求运行在页面上下文（`@grant none`、`@sandbox raw`）。

## 本地开发：免重复复制（Chrome / Edge）

工程会同时生成 `dist/swarm-mmo-local.user.js`，其中 `@require file:///...` 指向当前工程的 `dist/swarm-mmo.user.js`。这是 [Tampermonkey 官方提供的本地编辑方式](https://www.tampermonkey.net/faq.php?q=Q402)。

首次配置：

1. 运行 `pnpm build` 或 `pnpm dev`。
2. 打开 Chrome / Edge 的扩展管理 → Tampermonkey → 详情，开启「允许访问文件网址」。[官方设置说明](https://www.tampermonkey.net/faq.php?q=Q204)
3. 在油猴新建脚本，将 `dist/swarm-mmo-local.user.js` 的完整内容复制进去并保存，只需一次。
4. 停用之前直接复制安装的「Swarm MMO 助手」，仅保留「Swarm MMO 助手（本地开发）」启用，避免旧版抢先执行。

以后启动 `pnpm dev`，源码保存后自动重新打包，**刷新游戏页面即可使用新代码**，不需要再次复制。没有运行监听时，改完代码执行 `pnpm build` 再刷新也可以。刷新不会自动重启自动扩张。

注意：这不是对已打开页面热替换代码；加载器引用的是编译后的 JS，不能直接引用 `src/` 中的 TS / TSX。工程移动到其他路径后需要重新生成并安装加载器；若将来调整脚本的匹配网址或权限元数据，也需要更新加载器。生成文件包含本机绝对路径，仅供本地开发，不作为发布脚本分发。

如果出现本地文件访问被拒绝，先检查路径和文件访问开关；官方说明指出某些环境还要求扩展的站点访问权限为「所有网站」。此方式按官方文档适用于 Chrome 及其衍生浏览器；其他浏览器需另选开发加载方式。

## 分区运行（v0.11.0）

自动扩张与进攻可以同时开启，独立设置区域、启动和停止，共享兵力预算，使用独立派兵队列。进攻固定每秒最多一次；扩张按设定的 1～2 秒基准加入 ±0.2 秒随机量，最短 1 秒。不会随安装、刷新或页面恢复自动启动；已手动启动的扩张支持后台运行和断线自动恢复。

建议大量星球按区域运行：

1. 在游戏地图移动到准备进攻的位置，切换「进攻模式」，点击「用地图视野中心」；也可以先选中一颗星球，点击「用选中星球」。
2. 调整区域半径，点击「加载区域与敌人」，查看己方、无主、敌方星球数量。
3. 从区域内的敌人列表选择玩家，可按名字或 ID 筛选，也可定位该敌人的一颗星球。默认针对区域内所有非盟友，始终排除自己与同联盟成员。
4. 进攻可自动选择 1～3 个集结据点（默认 3 个），也可指定一个初始己方中转星（区域列表或直接读取地图所选行星）。附近能拿点的来源直接进攻，其余兵力按需集结；指定中转星只限制集结，不限制其他来源直攻。可选择攻下集结目标后前移对应据点，始终留在原战区内。
5. 在「自动扩张」切换到「固定区域」，用同样的方法选择另一片区域，然后分别启动两个模式。

**区域同时约束出兵来源和目标。** 固定中心与半径不会随着占领自动外移；新占领的区域内星球可以参与后续任务。扩张保留「全部领地」选项以兼容旧配置，但大量领地推荐分区。首版每个模式配置一个圆形区域；需要调整区域或敌人时先停止对应模式。

进攻首次扫描若发现战区内没有己方星球，或全部来源启用了游戏原生自动化，会直接停止进攻、展开设置并给出原因，不停止扩张。区域概览也会提示最近己方星球与中心的距离。旧战区坐标和指定敌人保持不变；区域应跨过敌我交界，不能只圈住敌人。运行时显示无预算、搜索距离内无目标、航时超限、兵力不足、报价不可用与在途锁定等诊断。

左下角收起状态同时展示两种模式的状态和最新日志。启动后折叠设置，展示动作、扫描、队列与结果；切换 Tab、收起面板不会停止任务。可以单独停止一个模式，或点击「全部停止」。日志按模式展示，每种模式最多 50 条、合计最多 100 条，扩张的新日志不会挤掉进攻的停止原因，连续重复状态不刷屏。

面板下方常驻显示 `Swarm 助手 v0.15.4`，展开和收起都可见。版本来自实际运行包的 `package.json`，不是油猴本地加载器的旧元数据；刷新后可据此确认浏览器是否加载了新脚本。

v0.15.4 前线快速检查支持附近无主星合兵，不必等全量规划完成。仍使用原生批量发射，核验所有参与来源的实时预算、8 格相互距离、15 秒抵达时差、损耗和目标锁。新增来源的补覆盖与周期扫描计时分开，不重置正在运行的规划和已有倒计时；日志明确标记「补充覆盖」。报价规则指纹不再受 SDK 返回行顺序影响，真实科技 / 覆盖规则变化丢弃草案时会说明原因。

v0.15.3 对「预估能打、原生报价却不可行」的来源也限制单轮评估量。首轮每颗来源最多评估 n 个候选，后续复核最多 n 个保留候选，再评估最多 n 个候选；未检查的范围保存位置，下轮继续，不因输入不变而缓存成永久无方案。近邻优先，明显增兵重查附近，已有足够可行候选时继续复用。日志显示剩余候选待续查的来源数。全局规划在调度等待较长时把计算片段从 8ms 小幅调整至最多 12ms，保持后台优先级；前线和进攻仍用原短片段。

v0.15.2 修复合兵来源的候选报价放大：已有足够附近合兵候选后，不再为等待单星可行目标继续报价数十条只能合兵的路线；仍在原候选范围内寻找可单星完成的目标。合兵航路在自然产兵后继续复用。新占星球立即补覆盖，占领结果从活动内存订阅更新，不再等全量规划结束；库存确认屏障与共享预算保持独立。

v0.15.1 将前线 / 后勤短规划改为独立计时器分片，避免等待全量规划的后台优先级调度。前线按未检查时间轮询，先排除明显不可打目标，再截取候选；首个有效来源即补队列。成功的无主目标报价可跨自然产兵复用，实际派兵仍核验当前预算。耗时面板增加分片计算 / 调度等待 / 恢复检查、原生报价平均及最大耗时、官方库存遍历和库存同步次数，区分计算成本与网络等待。

v0.15.0 增加持续前线补给、恒星大规模分批募集和前线占领时间比较。已有目标与在途补给持续保留；每批最多 50 颗来源，不受直接合兵的 1～10 颗上限限制。新增「耗时与数据来源」以及募集进度、缺口和预计占领时间。

v0.14.3 将已规划的后方升级合并为原生批量请求，每批最多 200 颗、每颗只升一级，共用一次操作间隔。扩张占领任务仍优先；提交前逐颗复核等级、库存、防守与任务预留，失效项跳过。日志按批汇总，同步后按实际等级提升核实成功数量；拒绝或结果未知不拆分重发。

v0.14.2 优先筛选附近可打目标，并复用未变化的原生报价。扩张约每秒监测补兵：明显增兵的来源优先做小批附近规划；首次全局规划较慢或队列接近耗尽时，也会轮流检查可用兵力较多的来源。附近新机会按航程补入同一队列，保留已有占领任务的数量分配，未执行的后方升级让位。恒星、合兵等完整规划继续进行，不必等它结束才能出兵；仍受防守、任务预留、连接和情报校验限制。

当前动作与最近事件分开显示：可查看全局规划阶段、已检查来源数、累计耗时、前线增量规划、待执行数量和后台回执 / 库存同步数量。收起后的状态徽标也反映当前工作，不再用一条旧的升级回执表示全部运行状态。

v0.14.1 修复游戏 CSP 拦截 Blob Worker 导致的「后台规划线程异常」和反复扫描；改用后台优先级分片计算，慢评估期间仍连续执行已有队列，无需修改浏览器安全设置。

v0.13.1 修正陨石表的适配名称为 `meteorite2`（连接读取与订阅 SQL 一致），解决 v0.13.0 默认开启陨石占领时反复提示「陨石情报接口不可用」、无法完成首次扫描的问题。

## 快速扩张、恒星与陨石（v0.13.0）

默认选择「快速铺开」，持续消费队列，不等待整波舰队落地。每轮先安排至多一颗当前有足够兵力的无主恒星，剩余预算对无主星球与陨石按占点数更多、舰队更少、航程更短分配。恒星可占机会优先于普通占点，因此包含恒星的完整计划不宣称全局最大占点数。两种模式继续共享真实库存、防守和任务预算。

- **恒星**：默认开启，仅占无主恒星。使用原生行星到恒星报价与接口；基础 100 探针转换为 1 超级信标，有驻军时需要超过驻军数量，科技和跨星系损耗以原生报价为准。不会额外把报价中的探针数再乘 100，也不为零驻军恒星强制多派一个超级信标。
- **后方持续补给**：分别保留一个无主行星前线计划和一个恒星募集计划，来源限于固定战区及最长航程，允许数百甚至更多来源参与。每批最多 50 颗，使用原生批量接口；当前库存与已知在途足以完成目标才发出新增补给，计入两段损耗和防守留兵。每批后继续推进原目标，实际到账后才从前线单星出击；有附近可立即占领的目标时先处理。补给与占领任务交替执行，共享扩张限速。目标或据点失效释放未用预留，未知来援暂停追加，不重复计算已发补给。
- **陨石**：默认开启，使用原生陨石报价与派兵接口，仅占无主陨石。规划按实际排队位置检查到期时间，出队再次检查，必须在消失前至少 5 秒抵达。陨石没有产量，不能升级；到期时的持有人才获得奖励，驻军与尚未抵达的舰队会随之消失。当前仅支持单来源占陨石。
- **风险取向**：快速模式接受前沿暴露目标；可选「稳健扩张」暂缓敌人比己方更近、且没有 8 格内己方支援的孤立目标。这是已观测地图的地理启发式，不是敌方 ETA 或胜率预测，不会降低已知来袭的守军要求。
- **收益评估周期**：默认 3 小时，独立于队列窗口与最长航行。超过两分钟航程的行星仍有产能收益；收益只用于现有排序的后续比较，不替代占点数与速度优先。

「按收益与占领时间升级」默认开启，也可以关闭。后方升级仅选择连续观察稳定 10 分钟、无警戒范围内敌人和任何在途舰队、没有附近无主星球 / 已启用的恒星或陨石机会、且未被进攻或扩张任务使用的己方行星。每次调用原生接口升一级，保留防守预算，以未折扣的 `100 × 等级²` 作为费用上界与基础回本分钟数；回本须在收益评估周期内。默认 3 小时仅允许满足条件的一级行星升二级。不会开启永久服务器自动升级；已有原生自动化来源继续排除。刷新、重启或连接恢复后重新观察稳定时间。

前线另外比较「继续攒兵 / 后方补给」与「先从 1 升到 2」的预计占领时间。计入升级费用、生产周期、航行与分批发射时间；只有升级明确更快，且满足稳定观察、无邻敌 / 来袭与回本限制才升级。科技、库存、来援或目标变化会重新核算，不用预测产量直接派兵。

面板显示本轮选择原因、各类已确认占领、升级次数、已提交兵力和占领时新增基础产能；30 / 60 分钟保有统计只统计已到观察期限的行星与恒星，期间观察到丢失后再夺回也不算持续保有。陨石到期不计领土丢失。统计仅保留当前运行会话，最多跟踪最近 1,000 次未到期占领；未持续在线观察的时段不代表真实连续持有证明。

## 星球在途兵力（v0.12.2）

打开游戏的行星圆形操作菜单或以行星为目标的派兵圆盘，菜单下方先显示一个 32px 的雷达图标按钮（悬停提示「查询在途兵力」），不展示标题或大面板，点击后才额外订阅数据并显示「敌方在途」「我的在途」兵力和舰队数量；有同联盟舰队时另列「盟友在途」。统计的是飞往该星球的全部已订阅舰队，包括手动和原生自动化派出的舰队，不包含从该星球飞往别处的舰队。目标取自当前菜单，不会误用已选中的出兵来源。暂不支持恒星、基地和彗星菜单。

这项提示独立于扩张和进攻运行，助手收起时也有效。菜单约每 250ms 在本地检查一次，未点击时不额外请求数据；点击查询后兵力约每秒更新；靠近屏幕底部时提示会移到菜单上方或侧边。只有查询按钮接收操作，统计文本保持鼠标穿透。关闭菜单、切换目标、连接变化或卸载页面时释放本功能的订阅，不影响两种自动模式的订阅。

切换目标、身份或连接，以及关闭后重新打开菜单，均需要再次点击查询。重复点击不会重复建立订阅。点击后显示「加载中」，舰队和联盟订阅均确认后才显示数字；订阅失败或超时显示「数据不可用」，点击「重新查询」可手动重试，不自动请求。缺失兵力的舰队仍计入支数，并显示「未知」或已知兵力下界。兵力按服务器舰队记录汇总，**不是扣除跨星系航行损耗后的抵达兵力，也不是战斗胜负预测**。

## 游戏连接

使用当前页面的登录身份和 SpacetimeDB 连接；不读取登录令牌，也不新建游戏连接。地图 canvas 的 React Fiber 发现集中在 `src/game/session.ts`；游戏更新导致接口变化时停止并提示，不猜测发射。区域订阅、舰队读取和派兵适配集中在 `src/game/expansion-world.ts`。

## 代码组织

```text
src/
  main.ts                 # 油猴入口
  app/                    # 应用装配、控制器、设置存储、挂载与清理
  ui/                     # React 面板组件与独立 CSS
  game/                   # 游戏连接、订阅、类型与自动操作适配
  features/
    commander/            # 双模式调度、共享预算、动态留兵和固定战区
    attack/               # 单星进攻、大规模己方集结和据点推进
    expansion/            # 无主星候选、规划器、合兵算法、World 接口
  runtime/                # 跨标签页锁、操作限速、计算分片、未知结果保护
  shared/                 # 共用几何与候选筛选函数
scripts/                  # 构建与测试入口
tests/                    # 按功能拆分的测试和共用 fixtures
docs/                     # 架构与游戏研究记录
AGENTS.md                 # 项目协作约定和需要保持的业务规则
```

面板使用 React 组件、受控表单和 `useSyncExternalStore`。控制器独立管理游戏副作用，组件重新渲染不会重建调度器。样式仍隔离在 Shadow DOM 内，保留左下角布局和原有设置存储键。

React、React DOM 与 CSS 一起内嵌进单个油猴 JS，不引用游戏自己的 React，不新增远程依赖。`pnpm build` 生成压缩生产包；`pnpm dev` 生成包含 React 开发诊断的可读包。原有本地加载器可继续使用，重新构建后刷新游戏即可。

新增功能的放置原则、状态生命周期与验证方法见 [架构说明](docs/architecture.md)；协作规则见 [AGENTS.md](AGENTS.md)，游戏内部接口的研究依据见 [研究记录](docs/research.md)。

## 参数与共享调度

| 参数 | 默认值 | 范围 / 行为 |
| --- | --- | --- |
| 扫描间隔 | 10 秒 | 10、30、60、120 秒；从本轮规划完成后计时，双模式采用较快的扫描周期 |
| 每颗来源候选数 n | 10 | 1–50，优先附近可打目标，不足时用成本、产量与附近机会补位 |
| 最大搜索距离 | 32 | 1–128；单次来源到目标的距离，仍受固定区域约束 |
| 扩张操作间隔 | 1.5 秒 | 基准 1–2 秒，随机 ±0.2 秒、最短 1 秒；设为 1.2 秒时实际为 1.0～1.4 秒 |
| 进攻操作间隔 | 1 秒 | 固定值；直攻与集结共用进攻队列，不占扩张队列时隙 |
| 扩张规划队列窗口 | 120 秒 | 10–600 秒；限制预计排队时间，不要求在窗口内抵达 |
| 扩张最长航行时间 | 30 分钟 | 10–14,400 秒；独立限制单次航程，旧配置自动补入默认值 |
| 进攻规划队列窗口 | 120 秒 | 10–600 秒；只限制派兵排队，直攻与补给均占用时隙 |
| 进攻最长航行时间 | 30 分钟 | 10–14,400 秒；独立于队列窗口，不再要求两分钟内抵达 |
| 最低留兵 | 0 | 与前线比例取较大值，另外预留已知来袭所需守军 |
| 前线留兵比例 | 25% | 0–90%；警戒范围内有敌人才使用 |
| 敌方警戒距离 | 16 | 1–128 |
| 进攻占领后额外留兵 | 10 | 2–1,000,000 |
| 集结补给最长航行 | 30 分钟 | 1–240 分钟，独立于向敌方目标进攻的航行上限 |
| 同时集结据点数 | 3 | 自动选择 1～3 个；指定中转星时为 1 个 |
| 占领后前移中转星 | 开启 | 可以关闭以保留初始中转星 |
| 无主星协同来源数 | 3 | 数字输入 1～10；1 表示仅单星，敌方星球仅单星进攻 |

同一来源的可用兵力为：当前库存减去动态守军、未同步的已发射扣款和另一模式的任务预留。重叠战区使用更严格的留兵要求；不从区域外借兵。已知敌方来袭按抵达时间排序，对每一批之前的累计敌军按最大攻击加成 2 倍留兵，只抵扣该时点之前的基础产兵（每级每分钟 1 兵，额外留出 1 分钟缓冲）。每个较早时点都必须守得住，不用最后一批抵达前的产量抵挡前面的攻击。固定留兵 / 前线比例仍保留，不预支友军补给或科技收益；缺失来袭数量或时间的来源不出兵。使用游戏原生自动升级或自动转发的来源不参与，避免同时消费库存。

两种模式各自规划和执行，进攻不等待扩张的计算分片、操作间隔或发射回执；进攻计划先预留所需兵力，扩张使用剩余预算。可以在预计两分钟自然生产内补齐时短期攒兵，最多预留 120 秒；超时释放并冷却 60 秒。停止进攻立即释放未使用的预留。每个队列最多处理一个发射任务，并同步预扣共享库存。进攻出队时重新报价；扩张直接使用本轮规划好的数量与合兵分配，连续出队，不逐项重新报价或重算全战区，只保留连接、停止、归属、目标在途变化和涉及来源的共享库存 / 防守保护。

每轮周期覆盖扫描完成后先规划，等本轮两种活动模式的规划均完成，再开始扫描倒计时。例如规划用时 8 秒、扫描间隔 30 秒，则从规划结束再等 30 秒；不等待发射确认、库存同步或整条队列执行完毕。新增来源提前触发补覆盖，但不清除当前规划或重置倒计时；补覆盖期间全局规划完成也能正常启动计时。周期扫描和新一轮评估期间保留扩张队列并继续发射；新结果按最新内存库存、在途目标与进攻预留合并到剩余队列，不清空重来。停止、配置改变或连接失效仍取消旧扩张任务；局部覆盖规则变化只释放受影响来源的任务，全局草案继续分配其他有效候选，不整轮重启。科技与星系规则变化仍使依赖它们的报价失效。

进攻在两次扫描之间继续执行已排好的直攻 / 集结队列，不再每发一项就重新规划整个战区。每项出队仍刷新敌情、原生报价和共享预算；报价增加只能使用当前任务与未分配的余兵，不能侵占后续任务预留。失效任务跳过并释放本项预留，周期扫描及队列耗尽时再评估新机会。

扩张发出请求后立即继续队列，不等待回执或库存同步；同一来源的未花费余量也可继续使用。共享预算取游戏库存和本地剩余库存上限的较小值，再留出防守与进攻预留，避免缓存尚未更新时超支，或更新后重复扣款。回执与短期库存订阅在后台处理，同来源仍有较新的待确认请求时不提前释放其本地上限。库存同步失败保留本地扣账，每 5 秒最多尝试一批、每批 24 颗来源，仅重试查询，不重发已提交任务。进攻仍保留其来源同步屏障。

操作间隔从实际发出请求开始计算，不追赶补发。扩张只等待下一次随机间隔，发射回执不会阻塞后续任务；预算不足的项跳过，不盲目重复提交。15 秒未收到回执或请求被拒绝时，记录并跳过，继续其他目标，不要求用户核对解锁。未确认目标仍保留一段在途保护时间，后续扫描再确认占领。进攻仍等自己的确认与库存同步，耗时计入固定 1 秒间隔。浏览器休眠或后台计时器降频会延后实际发送，脚本不能保证系统休眠时持续执行。

## 自动扩张

- 先排除不可补兵的在途目标，再按距离排列最近的 max(32, 8n) 个目标；不足时使用原有成本、产量和附近机会混合候选补位，两部分去重。后台规划首轮最多评估 n 个，后续最多复核 n 个保留候选并评估 n 个候选，报价失败也计入上限；未完成的搜索下轮接续。密集可行区域通常只需 n 次报价；不可行近邻不会导致一颗来源连续报价整个样本，混合补位范围也不会被永久截掉。
- 对明确无己方在途补兵的无主目标，先按当前攻击加成上界，以及本来源和最多允许数量的邻居余兵，判断是否连理想情况下都不可能占领。该上界忽略损耗、航时和邻居之间的限制，只用于省掉不可能方案的报价；不代替原生报价，不减少来源数量，也不跳过可能完成的合兵。
- 120 秒仅控制近期派兵队列，不再排除航程超过两分钟的目标。全部领地、距离 64 的旧设置保留原值，新增的最长航行默认 30 分钟，让有余兵的后方星球也能独立领取较远任务。实际距离、战区、留兵与航行损耗仍需通过检查。
- 单星规划时保持游戏 `quoteSend.exact.probes + 1` 的发送下限，并按航行损耗反推至少增加 1 个实际抵达探针所需的发送量；不会为满足库存而削减余量。无损耗、无科技加成时，驻军 1 和 2 分别需要 3 和 4，来源可用兵力达到 7 即可分两次派兵。
- 已有己方舰队时，只有数量、抵达时间和同星系无损耗条件可确认，才允许按无主星剩余需求补差额。不能确认损耗、已有其他玩家舰队、预计已经足够占领，或已有助手任务锁定时继续等待；不对敌方目标使用补兵算法。
- 扩张候选优化依次比较预计占领数（更多）、总占领耗时（更短，合兵取最后一支抵达）、舰队数（更少）、规划期收益（更高）、发送兵力（更少），队列先执行短航程。相同占点数先选更早完成占领的方案；抵达时间相同时优先单星。附近机会只是有限启发式，没有假设新殖民星球立即能承担下一次出征。
- 小规模最多 18 个目标、100 个方案、20,000 个搜索节点，完整搜索后才显示候选集最优；大规模限制为 128 个目标、每目标最多 8 个方案，再做有界分配。不是长期战略或所有可能分兵方式的全局最优。
- 使用空间索引查找邻近目标；有队列时直接连续执行；根据上一轮评估耗时，在队列即将用完前提前补充任务，空闲时约每秒重新评估。实际发射受扩张队列限速控制。每轮扫描的规划完成后启动覆盖扫描倒计时。范围不变时复用仍活跃的订阅，不重复等待服务器加载同样的区域；新占领来源触发提前扫描，补足覆盖后加入，无需等待下个周期。规划时同一同步片段内复用原生报价，让出主线程后刷新缓存；扩张出队不再报价，目标归属 / 在途或来源预算失效时跳过该项，不额外占用操作间隔。
- 大量星球时仍让全部来源参与规划。距离排序只保留所需的前 K 项，其余三种排序每轮共享一次并保留混合补位；空间筛选、原生内存报价、合兵和任务分配分片执行，使用 scheduler.postTask 的 background 优先级续跑，让到期的发射计时器先执行。全局扩张从 8ms 开始，调度等待较长时调整至最多 12ms；前线、进攻和特殊目标仍按约 8ms 分片。单次原生调用无法中断，因此不保证实际片段绝不超过预算。每项报价前检查时间预算，停止或配置改变会取消旧计算，迟到结果不入队。覆盖查询保留已有分组，仅补新增网格，避免新占一颗星就重建大片订阅。

- 扩张按来源与无主目标复用未变化的原生报价。目标数据或来源位置、归属、等级变化使相关报价失效；已有成功报价不因来源自然产兵或库存减少而失效，但预算不足仍不可派兵，失败报价会在库存变化时重算；身份、科技和星系几何变化使全局报价缓存失效；联盟、恒星 / 有效基地变化先判断各来源是否仍处于友方覆盖内，只重算受影响来源。候选排序、目标锁、补兵缺口和共享预算仍按当前快照评估。缓存最多 100,000 条、最长 10 分钟；原生航线未知时 5 秒后重试，停止、恢复或卸载时清空。敌方报价不跨轮复用；扩张己方补给航线按位置、所有权与规则版本独立缓存，兵力变化不使纯航路失效。运行日志显示新算 / 复用报价数，便于区分重复计算与首次计算成本。上一轮很慢时，提前补队列的阈值最多为 20 项，避免持续重算尚未消耗的完整队列。
- 运行面板展示本轮已安排 / 总来源数和具备可行方案的来源数；可展开查看最多 6 颗未安排来源（可用兵力较多的在前），区分无预算、范围内没有目标、目标已在途、航时超限或分配给其他更快来源等原因。

行星前线与恒星计划按最新可用兵力与旧队列一起合并，普通发射或回执不会使其反复失效。恒星任务无法执行时一并释放其预留，仍可执行的旧任务继续发射。

后台规划直接复用长期订阅的内存快照，不新增 HTTP 查询或全图拉取。只有新区域缺少覆盖、连接恢复，以及发射后的必要库存确认才补订阅。运行日志显示每轮评估耗时与合并后队列数量。实现面向当前 Chrome，使用 scheduler.postTask，不包含旧浏览器兼容层。游戏页面的 CSP 禁止 Blob Worker，因此采用主线程协作分片，扫描、规划与队列执行仍为独立任务；无需修改浏览器安全设置，发布物仍是单个 JS，无额外下载。

### 无主星多来源联合占领

「每个目标最多协同星球数」可以输入 1～10，默认仍为 3。上限不是必须参与的数量，同样占点数先比较完成占领的时间，时间相同时优先更少舰队。2～3 星保留最快 / 最强最多 6 颗候选的组合枚举；4～10 星从最多 20 颗候选中补充至多 32 个兼容组合，每组只比较 4 种顺序的优先 / 均衡分配，不做全排列。计算仍分片执行，这属于有界搜索，不保证遍历所有可能组合。

来源彼此距离最多 8，预计抵达时间相差最多 15 秒。分别计算每支舰队的损耗，最低抵达总兵力为无主驻军 +1+1；忽略己方 Assault 的正向加成，保持保守。

联合任务使用原生 `launchSwarmBulk({ kind: 0, targetId, launches })` 一次提交，计一次队列操作；任何来源失效则跳过整个批次，不降级成多次单星发射。多支舰队仍分别战斗，目标在途中被他人占领会改变结果。敌方合兵尚未实现。

排队期间保持本轮已规划的合兵分配，不再因产兵而重新报价或改成单星；单星 / 合兵优化集中在规划阶段。失败的批量请求不会拆成单支重试。

## 集结进攻与据点推进

仅针对固定区域内符合敌人筛选的非盟友行星。比较目标产量、距离、发送量与实际航行时间，选择可承担的单星方案。基础报价由游戏提供，包含目标自然产兵与攻防科技；额外计入一个生产周期的保守防御余量和占领后留兵，再按边境损耗换算。

先对战区内全部可用来源做多目标直攻分配，按占点数、总航时、舰队数、收益和成本比较；“近”由实际航时、搜索范围和资源需求共同决定，不只看坐标。不可执行候选不会直接占满 n 个名额，在有界样本内继续补位。队列窗口与最长航行分别校验，15 分钟航程也可以进入近期 120 秒的派兵计划。随后用剩余预算为尚未安排直攻的目标选择集结计划，比较集结加进攻的总抵达时间与所需兵力。直攻与补给都有任务时交替执行，多个据点的补给轮流执行；窗口外的直攻释放预留，集结等待期间继续直攻，任何来源的未预留余量仍可用于其他任务。

这是有界的两阶段优化：小规模直攻可求候选集内最优，集结在有限中转星 / 目标 / 来源中选取可行方案；不宣称包含未来生产、所有多步进攻和敌方行动的全局最优。

有任意其他舰队正飞往敌方目标时暂不进攻，以免把多场战斗误算成单次报价。当前不预测敌方未来发出的援军，不保证占领后永久守住；进攻模式不攻击恒星、基地或黑洞，也不追击到战区之外，扩张模式可占无主恒星。科技或其他必要情报接口缺失时停止；数百来源先集结到己方星球，真正攻敌仍由中转星单独发射，未实现直接多波攻打敌星。

### 大规模集结

- 初始中转星可在地图单选后读取，也可从区域己方星球目录按 ID / 坐标筛选。自动模式优先比较区域内有攻击路线的据点；中转星必须属于自己、位于战区内，且不能启用游戏原生自动升级 / 转发。
- 自动选址先检查航路可用性，再混合航程短与库存多的据点比较募集方案，避免远处高库存来源挤掉前沿可用据点。有已知敌军来袭的星球不作为集结据点。最多保留 3 个不同据点和目标，共享数量预算，不重复使用同一份兵力。
- 新建或前移据点时，先保留其他有效集结计划的据点和目标，避免为已经筹兵的同一目标再开一份集结。失效计划释放占用，其他来源的可行直攻仍可直接完成该目标。
- 进攻兵力不足时，混合附近和高库存来源，最多比较 1,000 个来源；来源数不受扩张的 1～10 星限制。每批最多 50 个来源，通过原生批量接口补给己方中转星，与直接进攻共用 1 秒队列，不占扩张队列时隙。
- 只有预计总资源足以完成当前集结目标才启动募集。估算计入各段损耗、排队时间、集结等待期间的敌方增长、中转星的守军缺口与前线留兵比例；原生占领报价暂不可得时使用更保守的攻防/生产上界。
- 预留各来源具体数量，余量仍能参与其他任务。库存到账前不发起敌方进攻；实际出击再次使用原生报价和最新预算，不以在途承诺代替库存。
- 界面逐个显示中转星、敌方目标、中转可用兵力、预计需求、补给在途和待募集来源数。发射统计包含补给舰队，占领统计只记录真正占领，不把给自己补兵计为占领。
- 中转星遭到来袭、归属或原生自动化状态变化时，不继续发出旧集结批次；目标战况改变则重新评估。每次集结有等待上限（补给最长航行 + 进攻最长航行 + 队列窗口 + 60 秒缓冲），超时释放未发射预留；已发舰队无法撤回。
- 开启据点推进时，确认攻下集结目标（或该据点没有其他集结任务时从中转星发起的目标）后前移对应据点，其他据点继续原计划。其他星球的独立直攻不打断正在进行的集结；关闭时保留初始选择。固定战区边界不变，旧中转星的余兵和已发补给仍可作为后续资源。
- 直攻与集结计算也按约 8ms 分片让出主线程。规划在副本中进行，停止、修改配置或并行库存变化时丢弃旧草案，完整完成后才发布预留与据点状态；实际派兵仍读取最新库存和报价。

## 生命周期与验证边界

- 收起 / 切换 Tab 继续运行；扩张在后台继续，进攻在后台暂停。扩张运行中连接或订阅失效时，每 5 秒尝试重建连接适配和扫描，待已有请求的有限清理结束后恢复；同时运行的进攻停止。身份变化会停止，刷新、页面缓存恢复和已明确停止后不自动启动。
- 停止一个模式取消其未发射任务，不影响另一个模式。已经提交的舰队仍可能继续航行；全部停止或卸载后，完成已发操作的清理再释放跨标签页锁和订阅。扩张每个后台观察最多等待 15 秒回执和 12 秒库存同步，不会因一个永不返回的请求无限阻塞清理。
- 发射确认不等于占领。后续扫描核实归属；在预计抵达后保留缓冲时间，不因缓存暂时看不到舰队而立即重发。
- 扩张超时、拒绝不会锁定操作；旧扩张 / 旧版单条超时标记在取得跨标签页锁后自动清理。进攻的未知结果仍停止两种模式并需要核对；迟到回执不会重启已停止的模式，也不能清除其他任务的标记。发射计数表示请求已提交，不代表服务器已执行或占领成功。
- 各标签页共享一个 Web Lock，防止多个助手重复消费库存；扩张、进攻分别保存各自的限速记录；游戏原生手动操作不受助手队列控制。参数保存在 localStorage，ID 不转换为浮点数，不读取令牌或修改游戏缓存。
- 固定战区只加载区域及警戒 / 科技覆盖缓冲带，仍订阅己方资产用于核对结果。32×32 网格去重、每查询最多 24 格、最多 3 个并发，超过 2048 格停止并提示。

验证使用 Node/JSDOM 模拟世界和本地浏览器模拟页面，不代表真实游戏服务器已接受所有新订阅或成功完成进攻。游戏内部地图方法与数据表来自当前公开前端的只读核对；不为验证代码在真实账号派兵。

后勤规划每次每类最多新增 128 次原生航路计算，持续复用已有结果；每次发现阶段最多评估 16 对附近据点与目标，不宣称全局最优。普通扩张在输入完全不变时复用整份提案，变化时依然复用未受影响的逐路线报价。规划不新增网络请求；SDK 活动订阅提供内存库存与情报，新增覆盖和发射后的库存确认仍需服务器同步。面板分别记录这些耗时，不能仅凭规划总耗时推断网络瓶颈。

设置项的详细说明收纳在对应标题旁的问号提示中，支持悬停、点击或键盘聚焦查看，Esc 关闭。操作间隔、队列窗口、航行时间、恒星 / 陨石和升级说明分别绑定各自字段；问号与复选框标签分离，查看提示不会切换设置。

前线短周期检查作为后台监测展示，不覆盖主动作与状态徽标；运行时保留固定的前线监测行，持续超过 2 秒的检查才显示耗时，避免短任务反复插入 / 移除内容造成面板抖动。停止与异常仍立即显示。

2026-11-03 实服只读采样：全量规划第 432 秒检查了 1547/3676 来源，分片计算约 259 秒、调度等待约 174 秒，累计原生报价 118,260 次；该测点的主要瓶颈是报价数量。v0.15.2 的 3676 来源合兵模拟中，首次报价评估从旧路径至少 294,080 次降至 36,760 次（减少 87.5%），自然产兵后的后续规划新增报价为零。模拟调用量改善不是实服墙钟耗时保证，初始覆盖仍需等待服务器返回。


## v0.15.5 陨石快速检查与局部规则更新

陨石不再等待全局行星规划完成，约每秒独立检查内存情报。每次至多检查 8 个陨石、每个目标至多 4 个附近来源，最多补入 3 项任务；未查完的目标与来源轮流续查。继续共用扩张队列、操作间隔、目标锁和共享兵力账本，不突破留守、进攻或后勤预留。排队、航行与至少 5 秒到期余量都要满足，实际出队再次检查寿命。

「当前动作」内新增可展开的「陨石快速检查」，最多显示 6 个目标。跳过原因包括范围内没有来源、预算不足或已预留、在途 / 排队锁定、航时超限、寿命不足和原生报价拒绝；原生能够提供时显示航时、损耗和需求兵力。出队跳过也写入运行日志。

报价规则按来源记录，局部覆盖改变不会丢弃整条队列或重启全局规划；受影响候选被移除，其余继续发布。快速检查只为实际访问的来源和目标生成缓存指纹，避免每秒编码全部数千颗星球。进攻同步释放来源屏障后立即唤醒快速检查；后勤草案发布前复核目标，避免向已经安排直接占领的目标重复集结。

本版性能与并发行为通过模拟测试验证；实服一轮用时、缓存命中率仍需更新后观察，不将报价次数下降等同于实服墙钟同比提速。


## v0.15.6 附近合兵与远处单星比较

同样能占领这些目标时，先比较完成占领的总耗时，再比较舰队数量。合兵以最后一支舰队抵达的时间为准；一次原生批量派兵仍只占一个操作时隙。更快的附近合兵不会仅因使用两三支舰队而输给远处单星；时间相同才优先更少舰队。全局精确搜索、有界候选裁剪和贪心初始方案使用一致顺序，占点数仍优先。

前线快速检查找到单星可行方案后，也会围绕目标查询附近来源，不再只找第一颗大兵源周围的协同来源。比较最多 10 颗近邻与 10 颗强来源（去重），仍受整批 96 次原生路线评估上限与分片约束；附近兵力按攻击上界明显不足时省略额外报价。保留共享预算、留守、损耗、距离 8、抵达时差 15 秒、协同数量和原生批量发射约束。已经在途的任务继续受目标锁保护。

## 安稳发育模式

在「自动扩张」设置中选择「安稳发育：挂机占陨石」，手动启动后持续扫描并占领可及时抵达的无主陨石，暂缓孤立暴露目标。停止后才能切换模式；旧设置默认仍为自动扩张，切换不会覆盖原有的恒星、陨石或扩张取向偏好。

安稳发育复用扩张的独立队列、防守预算、固定战区、后台执行及断线恢复，关闭行星候选、前线检查和行星 / 恒星集结，不占行星或恒星。无陨石时持续等待；陨石检查计入排队、航程及到期安全余量。可继续使用「按收益与占领时间升级」，遵守连续稳定、无邻敌 / 来袭、无附近无主陨石机会和回本周期限制；未选择的行星 / 恒星目标不阻止升级。进攻仍独立控制，和平挂机时需自行停止进攻。刷新后不会自动启动。
