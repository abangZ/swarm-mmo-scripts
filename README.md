# Swarm MMO 助手

React + TypeScript + esbuild 工程，打包为一个独立的 Tampermonkey 油猴脚本，无运行时 CDN 依赖。

## 开发与构建

需要 Node.js 22+ 和 pnpm 10.34.5（版本已在 `packageManager` 中固定）。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm typecheck
pnpm dev      # 监听源码并重新打包；配合本地加载脚本，刷新游戏即可加载更新
```

输出：`dist/swarm-mmo.user.js`。在 Tampermonkey 中新建脚本，将此文件完整内容粘贴并保存，随后刷新游戏 `/play` 页面。后续重新构建后，需要重新替换已安装脚本的内容。脚本要求运行在页面上下文（`@grant none`、`@sandbox raw`）。

## 本地开发：免重复复制（Chrome / Edge）

工程会同时生成 `dist/swarm-mmo-local.user.js`，其中 `@require file:///...` 指向当前工程的 `dist/swarm-mmo.user.js`。这是 [Tampermonkey 官方提供的本地编辑方式](https://www.tampermonkey.net/faq.php?q=Q402)。

首次配置：

1. 运行 `pnpm build` 或 `pnpm dev`。
2. 打开 Chrome / Edge 的扩展管理 → Tampermonkey → 详情，开启「允许访问文件网址」。[官方设置说明](https://www.tampermonkey.net/faq.php?q=Q204)
3. 在油猴新建脚本，将 `dist/swarm-mmo-local.user.js` 的完整内容复制进去并保存，只需一次。
4. 停用之前直接复制安装的「Swarm MMO 助手」，仅保留「Swarm MMO 助手（本地开发）」启用，避免旧版抢先执行。

以后启动 `pnpm dev`，源码保存后自动重新打包，**刷新游戏页面即可使用新代码**，不需要再次复制。没有运行监听时，改完代码执行 `pnpm build` 再刷新也可以。刷新不会自动重启自动扩张。

注意：这不是对已打开页面热替换代码；加载器引用的是编译后的 JS，不能直接引用 `src/` 中的 TS / TSX。工程移动到其他路径后需要重新生成并安装加载器；若将来调整脚本的匹配网址或权限元数据，也需要更新加载器。生成文件包含本机绝对路径，仅供本地开发，不作为发布脚本分发。

如果出现本地文件访问被拒绝，先检查路径和文件访问开关；官方说明指出某些环境还要求扩展的站点访问权限为「所有网站」。此方式按官方文档适用于 Chrome 及其衍生浏览器；其他浏览器需另选开发加载方式。

## 面板使用（v0.5.0）

- 功能按「自动扩张 / 进攻模式」Tab 分栏；进攻模式暂为开发中占位，不执行进攻。原「发送到最近无主星」功能已移除。
- 左下角缩小面板显示运行状态和最新一条带时间的日志；点击展开。收起与切换 Tab 都不会停止扩张。
- 自动扩张启动后自动收起设置，优先展示当前动作、统计、派兵队列和日志。运行中可以展开查看参数，停止后才能修改。
- 状态区区分扫描、排队、发送并等待确认、等待目标或兵力、后台暂停、停止及异常。展示己方星球数、候选目标数、最近扫描时间和下次扫描倒计时。
- 日志记录扫描、发射确认、占领结果和异常，最新在前，保留当前面板会话最近 100 条；连续重复状态不重复记录，刷新后不保留。
- 发射确认不等于占领；占领结果在扫描后核实。未知结果需要核对游戏日志与在途舰队，再通过底部恢复区解锁。

## 游戏连接

使用当前页面的登录身份和 SpacetimeDB 连接；不读取登录令牌，也不新建游戏连接。地图 canvas 的 React Fiber 发现集中在 `src/game/session.ts`；游戏更新导致接口变化时停止并提示，不猜测发射。区域订阅、舰队读取和派兵适配集中在 `src/game/expansion-world.ts`。

## 代码组织

```text
src/
  main.ts                 # 油猴入口
  app/                    # 应用装配、控制器、设置存储、挂载与清理
  ui/                     # React 面板组件与独立 CSS
  game/                   # 游戏连接、订阅、类型与自动操作适配
  features/
    expansion/            # 扩张引擎、规划器、合兵算法、World 接口
  runtime/                # 跨标签页锁、操作限速、未知结果保护
  shared/                 # 共用几何函数
scripts/                  # 构建与测试入口
tests/                    # 按功能拆分的测试和共用 fixtures
docs/                     # 架构与游戏研究记录
AGENTS.md                 # 项目协作约定和需要保持的业务规则
```

面板使用 React 组件、受控表单和 `useSyncExternalStore`。控制器独立管理游戏副作用，组件重新渲染不会重建扩张引擎。样式仍隔离在 Shadow DOM 内，保留左下角布局和原有设置存储键。

React、React DOM 与 CSS 一起内嵌进单个油猴 JS，不引用游戏自己的 React，不新增远程依赖。`pnpm build` 生成压缩生产包；`pnpm dev` 生成包含 React 开发诊断的可读包。原有本地加载器可继续使用，重新构建后刷新游戏即可。

新增功能的放置原则、状态生命周期与验证方法见 [架构说明](docs/architecture.md)；协作规则见 [AGENTS.md](AGENTS.md)，游戏内部接口的研究依据见 [研究记录](docs/research.md)。

## 自动扩张

在「自动扩张」Tab 中，设置参数后点「开始扩张」。不会随安装、刷新或重连自动启动。

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| 扫描间隔 | 10 秒 | 下拉选择 10、30、60、120 秒 |
| 每颗己方星球的最近候选数 n | 10 | 1–50 |
| 最大搜索距离 | 32 | 1–128 个地图坐标单位 |
| 全局操作间隔 | 1.5 秒 | 1–2 秒 |
| 规划时间范围 | 120 秒 | 10–600 秒 |
| 每颗星球留守兵力 | 0 | 非负整数 |
| 每个目标最多协同星球数 | 3 | 1（仅单星）、2、3 |

自动扩张使用游戏 `listOwnedBodies()` 读取计入增长的兵力，使用 `quoteSend()` 取得占领报价与航行时间。**单星方案的规划和出队校验均以 `quoteSend.exact.probes + 2` 为发送量**；如果加 2 后库存不足，会等待，不会缩减安全余量。该余量提高容错，但不能保证目标在航行期间不被其他玩家改变。

每颗出发星球在完整加载的搜索半径内，排除己方在途舰队已锁定的目标，再选最近 n 个无主行星。合并后的候选统一比较单星与 2～3 星联合方案，不向已有主人的目标发起新任务。新占领星球在下一轮扫描后参与扩张。手动从游戏发出的己方舰队也会锁定目标，保守地等到该舰队抵达后再决定是否需要补兵。

优化目标依次为：时间范围内预计占领数最多、预计总抵达时间最短、总发送数量最少。每个目标最多分配一个单星或合兵方案，各出发星球的派兵总额不能超过扣除留守和临时预留后的库存；排队时间计入预计抵达时间。至多 18 个目标、100 个可行单星/合兵方案时执行最多 20000 个搜索节点的分支搜索，完整搜索结束才显示「当前候选集最优方案」。更大的规模或搜索达到上限显示「有界优化方案」，采用多轮启发式分配作为基线。最优仅指当前候选与静态兵力模型，不包含未来增兵、敌方行动、新殖民星球的再扩张及实际网络延迟。

执行中每次只取队首一个任务，发送前重新检查报价、每个参与星球的库存、留守、目标归属、在途舰队和连接。后续队列重新规划。已确认发射的兵力会保守预留到下一次完整扫描，避免缓存尚未同步时重复使用；这可能短暂低估可用兵力。

面板展示队列前 5 项（包含所有参与星球）、已发舰队数、确认占领数、未占领数和锁定目标数。一次合兵任务只算一个目标，但计入 2～3 支舰队。发射确认不计为占领，统计在下一次扫描、舰队离开在途集合后核对归属。统计只覆盖本轮由助手派出的舰队。

### 2～3 星联合占领

- 默认允许最多 3 颗星球协同，可以选择 2 颗或关闭合兵（1 颗）。旧版保存的参数会保留，并默认补上 3 颗的协同上限。
- 每个目标从其候选来源中取预计航行最快的最多 6 颗，枚举两两/三方组合。参与星球彼此距离最多 8 个坐标单位，预计抵达时差最多 15 秒；每颗来源到目标仍需满足搜索半径和规划时间限制。
- 原生 `quoteSend` 在单星兵力不足时不给占领总报价。因此合兵使用**无主行星当前驻军 +1（胜出）+2（安全余量）**作为最低实际抵达兵力，按每支舰队各自的边境损耗和整数取整反推发送量。忽略攻击科技的正向加成，以免高估战斗力。这可能比充分利用科技加成更保守。
- 例如目标有 10 驻军，两颗星球各有 8 个可用探针且无损耗，可以合计发出 13 个；三颗各有 5 个也可以合计发出 13 个。余量按整个联合任务计算，不是每支舰队额外再加 2。
- 无主目标没有所属玩家的防御/韧性科技，按无主目标计算；不能将此算法用于攻击玩家星球。游戏的多支舰队实际上分别结算，目标在途中被其他玩家抢占等情况仍可能改变结果。
- 多种分配方式（优先用某一来源、均衡分担）进入统一规划，优化器会同时预留所有参与者的兵力。同样能占领时可选择更快的合兵，也可能保留单星方案把其他来源留给另一个目标。这里的最优仍仅指枚举出的候选方案，不是所有可能的兵力分配。
- 执行时重新计算整组方案。任何来源失去归属、兵力不足、目标已有主或已存在己方在途舰队，都撤销该次未发出的任务，重新规划。
- 使用原生 `launchSwarmBulk({ kind: 0, targetId, launches })` 一次提交所有来源，作为一次操作共用 1～2 秒限速；各舰队依旧按自己的航行时间抵达，不保证同一时刻到达。服务器返回错误时停止并锁定结果，不拆成单支请求重试。
- 本地对整个目标保持一个在途锁，预留所有来源的发送兵力，直到后续扫描确认结果。任意一支舰队仍在途时不另开一个针对同一无主目标的任务。

### 停止、后台与异常

- 收起面板仍继续扩张；切到后台时暂停发射，回到前台重新扫描，不补发错过的定时操作。
- 离开页面时停止扩张并卸载面板；通过浏览器前进/后退缓存返回时重新显示助手，但需手动启动扩张，原有未知结果锁定仍然保留。
- 点击停止立即取消未发出的任务；正在等待服务器的请求无法撤回。未完成的扫描会先收尾再释放订阅。
- 使用 Web Locks 限制同一网站来源最多一个助手执行者。各助手实例共用操作锁和限速记录；游戏原生拖拽操作不受助手限速控制。
- 断线、身份变化、订阅失效会停止，需手动重新启动。
- 发射前写入本地未确认标记；成功确认后删除。超时、拒绝或刷新中断时保守锁定，绝不自动重试。先核对游戏日志与在途舰队，再在「发射结果未知时恢复」中勾选确认并解除锁定。成功的延迟确认也可以清除对应标记，但不会自动重启扩张。
- 参数保存在该网站的 localStorage；不保存登录令牌。跨来源（例如不同子域名）的浏览器锁不共享。
- 区域订阅按 32×32 网格去重，每条查询最多 24 个网格，最多并发 3 条查询。超过 2048 个网格时停止并提示缩小半径，避免无界加载。

### 自动化模块

- `src/game/expansion-world.ts`：地图报价、增长兵力、己方舰队和区域订阅。
- `src/features/expansion/planner.ts`：单星/合兵候选分配、各来源库存约束与队列时间优化。
- `src/features/expansion/cooperation.ts`：附近 2～3 个来源组合、独立航行损耗、联合兵力分配。
- `src/features/expansion/engine.ts`：扫描、规划、发送、在途跟踪及停止生命周期。
- `src/runtime/operations.ts`：跨标签页互斥、全局限速、结果未知锁定。
