# Swarm MMO 助手

React + TypeScript + esbuild 工程，打包为一个独立的 Tampermonkey 油猴脚本，无运行时 CDN 依赖。

## 开发与构建

需要 Node.js 22+ 和 pnpm 10.34.5（版本已在 `packageManager` 中固定）。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm typecheck
pnpm dev      # 监听源码并重新打包；配合本地加载脚本，刷新游戏即可加载更新
```

输出：`dist/swarm-mmo.user.js`。在 Tampermonkey 中新建脚本，将此文件完整内容粘贴并保存，随后刷新游戏 `/play` 页面。后续重新构建后，需要重新替换已安装脚本的内容。脚本要求运行在页面上下文（`@grant none`、`@sandbox raw`）。

## 本地开发：免重复复制（Chrome / Edge）

工程会同时生成 `dist/swarm-mmo-local.user.js`，其中 `@require file:///...` 指向当前工程的 `dist/swarm-mmo.user.js`。这是 [Tampermonkey 官方提供的本地编辑方式](https://www.tampermonkey.net/faq.php?q=Q402)。

首次配置：

1. 运行 `pnpm build` 或 `pnpm dev`。
2. 打开 Chrome / Edge 的扩展管理 → Tampermonkey → 详情，开启「允许访问文件网址」。[官方设置说明](https://www.tampermonkey.net/faq.php?q=Q204)
3. 在油猴新建脚本，将 `dist/swarm-mmo-local.user.js` 的完整内容复制进去并保存，只需一次。
4. 停用之前直接复制安装的「Swarm MMO 助手」，仅保留「Swarm MMO 助手（本地开发）」启用，避免旧版抢先执行。

以后启动 `pnpm dev`，源码保存后自动重新打包，**刷新游戏页面即可使用新代码**，不需要再次复制。没有运行监听时，改完代码执行 `pnpm build` 再刷新也可以。刷新不会自动重启自动扩张。

注意：这不是对已打开页面热替换代码；加载器引用的是编译后的 JS，不能直接引用 `src/` 中的 TS / TSX。工程移动到其他路径后需要重新生成并安装加载器；若将来调整脚本的匹配网址或权限元数据，也需要更新加载器。生成文件包含本机绝对路径，仅供本地开发，不作为发布脚本分发。

如果出现本地文件访问被拒绝，先检查路径和文件访问开关；官方说明指出某些环境还要求扩展的站点访问权限为「所有网站」。此方式按官方文档适用于 Chrome 及其衍生浏览器；其他浏览器需另选开发加载方式。

## 分区运行（v0.10.0）

自动扩张与进攻可以同时开启，独立设置区域、启动和停止，共享兵力预算，使用独立派兵队列。进攻固定每秒最多一次，扩张保留自己的 1～2 秒间隔。不会随安装、刷新、重新连接或页面恢复自动启动。

建议大量星球按区域运行：

1. 在游戏地图移动到准备进攻的位置，切换「进攻模式」，点击「用地图视野中心」；也可以先选中一颗星球，点击「用选中星球」。
2. 调整区域半径，点击「加载区域与敌人」，查看己方、无主、敌方星球数量。
3. 从区域内的敌人列表选择玩家，可按名字或 ID 筛选，也可定位该敌人的一颗星球。默认针对区域内所有非盟友，始终排除自己与同联盟成员。
4. 进攻可选择初始己方中转星（区域列表或直接读取地图所选行星），也可自动选点。附近能拿点的来源直接进攻，其余兵力按需集结；选择中转星不会限制其他来源直攻。可选择攻下集结目标后前移中转星，始终留在原战区内。
5. 在「自动扩张」切换到「固定区域」，用同样的方法选择另一片区域，然后分别启动两个模式。

**区域同时约束出兵来源和目标。** 固定中心与半径不会随着占领自动外移；新占领的区域内星球可以参与后续任务。扩张保留「全部领地」选项以兼容旧配置，但大量领地推荐分区。首版每个模式配置一个圆形区域；需要调整区域或敌人时先停止对应模式。

左下角收起状态同时展示两种模式的状态和最新日志。启动后折叠设置，展示动作、扫描、队列与结果；切换 Tab、收起面板不会停止任务。可以单独停止一个模式，或点击「全部停止」。日志按模式展示，两个模式合计最多保留 100 条，连续重复状态不刷屏。

面板下方常驻显示 `Swarm 助手 v0.10.0`，展开和收起都可见。版本来自实际运行包的 `package.json`，不是油猴本地加载器的旧元数据；刷新后可据此确认浏览器是否加载了新脚本。

## 游戏连接

使用当前页面的登录身份和 SpacetimeDB 连接；不读取登录令牌，也不新建游戏连接。地图 canvas 的 React Fiber 发现集中在 `src/game/session.ts`；游戏更新导致接口变化时停止并提示，不猜测发射。区域订阅、舰队读取和派兵适配集中在 `src/game/expansion-world.ts`。

## 代码组织

```text
src/
  main.ts                 # 油猴入口
  app/                    # 应用装配、控制器、设置存储、挂载与清理
  ui/                     # React 面板组件与独立 CSS
  game/                   # 游戏连接、订阅、类型与自动操作适配
  features/
    commander/            # 双模式调度、共享预算、动态留兵和固定战区
    attack/               # 单星进攻、大规模己方集结和据点推进
    expansion/            # 无主星候选、规划器、合兵算法、World 接口
  runtime/                # 跨标签页锁、操作限速、计算分片、未知结果保护
  shared/                 # 共用几何与候选筛选函数
scripts/                  # 构建与测试入口
tests/                    # 按功能拆分的测试和共用 fixtures
docs/                     # 架构与游戏研究记录
AGENTS.md                 # 项目协作约定和需要保持的业务规则
```

面板使用 React 组件、受控表单和 `useSyncExternalStore`。控制器独立管理游戏副作用，组件重新渲染不会重建调度器。样式仍隔离在 Shadow DOM 内，保留左下角布局和原有设置存储键。

React、React DOM 与 CSS 一起内嵌进单个油猴 JS，不引用游戏自己的 React，不新增远程依赖。`pnpm build` 生成压缩生产包；`pnpm dev` 生成包含 React 开发诊断的可读包。原有本地加载器可继续使用，重新构建后刷新游戏即可。

新增功能的放置原则、状态生命周期与验证方法见 [架构说明](docs/architecture.md)；协作规则见 [AGENTS.md](AGENTS.md)，游戏内部接口的研究依据见 [研究记录](docs/research.md)。

## 参数与共享调度

| 参数 | 默认值 | 范围 / 行为 |
| --- | --- | --- |
| 扫描间隔 | 10 秒 | 10、30、60、120 秒；双模式采用较快的扫描周期 |
| 每颗来源候选数 n | 10 | 1–50，混合距离、成本、产量与附近机会 |
| 最大搜索距离 | 32 | 1–128；单次来源到目标的距离，仍受固定区域约束 |
| 扩张操作间隔 | 1.5 秒 | 1–2 秒，只控制扩张队列 |
| 进攻操作间隔 | 1 秒 | 固定值；直攻与集结共用进攻队列，不占扩张队列时隙 |
| 扩张规划队列窗口 | 120 秒 | 10–600 秒；限制预计排队时间，不要求在窗口内抵达 |
| 扩张最长航行时间 | 30 分钟 | 10–14,400 秒；独立限制单次航程，旧配置自动补入默认值 |
| 进攻规划时间范围 | 120 秒 | 10–600 秒；保留排队加航行的截止时间约束 |
| 最低留兵 | 0 | 与前线比例取较大值，另外预留已知来袭所需守军 |
| 前线留兵比例 | 25% | 0–90%；警戒范围内有敌人才使用 |
| 敌方警戒距离 | 16 | 1–128 |
| 进攻占领后额外留兵 | 10 | 2–1,000,000 |
| 集结补给最长航行 | 30 分钟 | 1–240 分钟，独立于向敌方目标进攻的航行上限 |
| 占领后前移中转星 | 开启 | 可以关闭以保留初始中转星 |
| 无主星协同来源数 | 3 | 1、2、3；敌方星球仅单星进攻 |

同一来源的可用兵力为：当前库存减去动态守军、未同步的已发射扣款和另一模式的任务预留。重叠战区使用更严格的留兵要求；不从区域外借兵。已知敌方来袭按最大攻击加成 2 倍保守预留，不抵扣未来自然产兵或己方防御科技；缺失来袭数量或时间的来源不出兵。使用游戏原生自动升级或自动转发的来源不参与，避免同时消费库存。

两种模式各自规划和执行，进攻不等待扩张的计算分片、操作间隔或发射回执；进攻计划先预留所需兵力，扩张使用剩余预算。可以在预计两分钟自然生产内补齐时短期攒兵，最多预留 120 秒；超时释放并冷却 60 秒。停止进攻立即释放未使用的预留。每个队列最多处理一个任务，发射前复核区域、归属、联盟、库存、来袭、报价和连接，并同步预扣共享库存；随后重新规划。

来源从发射前预扣到库存同步结束期间暂不被另一个队列使用，其他来源可同时发射；同步结束后同一来源的余兵可以继续服务两个模式。发射确认后，针对涉及的来源做一次短期库存订阅；新订阅确认后释放这些来源的本地扣款，不必等待 10～120 秒的完整扫描，也不会从已更新库存再扣同一笔兵力。库存同步失败会停止，不重发已确认操作。

操作间隔从实际发出请求开始计算，确认与库存同步耗时计入间隔，不在完成后再额外等待一个完整间隔；各队列分别等待自己的确认和库存同步，不追赶补发。库存同步完成后，利用本队列剩余操作间隔计算下一轮计划，出队时重新检查。1 秒是进攻的最短发射间隔，计算、扫描和服务器响应较慢时会延后。旧进攻间隔自动归一为 1 秒，扩张设置不变。

## 自动扩张

- 混合选取距离近、驻军少、单位成本产量高、附近还有便宜目标的候选。先排除不可补兵的在途目标，再在有界样本中核对航时和预算，用可执行方案补足 n，避免附近的高驻军目标占满名额；正常情况下只检查约 2n 个，有不足时最多检查 max(32, 8n) 个。
- 120 秒仅控制近期派兵队列，不再排除航程超过两分钟的目标。全部领地、距离 64 的旧设置保留原值，新增的最长航行默认 30 分钟，让有余兵的后方星球也能独立领取较远任务。实际距离、战区、留兵与航行损耗仍需通过检查。
- 单星保持游戏 `quoteSend.exact.probes + 1` 的发送下限，并按航行损耗反推至少增加 1 个实际抵达探针所需的发送量；不会为满足库存而削减余量。无损耗、无科技加成时，驻军 1 和 2 分别需要 3 和 4，来源可用兵力达到 7 即可分两次派兵。
- 已有己方舰队时，只有数量、抵达时间和同星系无损耗条件可确认，才允许按无主星剩余需求补差额。不能确认损耗、已有其他玩家舰队、预计已经足够占领，或已有助手任务锁定时继续等待；不对敌方目标使用补兵算法。
- 扩张候选优化依次比较预计占领数（更多）、舰队数（更少）、总航行时间（更短）、规划期收益（更高）、发送兵力（更少），队列先执行短航程。相同占点数优先单星；合兵能解放关键来源、增加占点数时仍会使用。附近机会只是有限启发式，没有假设新殖民星球立即能承担下一次出征。
- 小规模最多 18 个目标、100 个方案、20,000 个搜索节点，完整搜索后才显示候选集最优；大规模限制为 128 个目标、每目标最多 8 个方案，再做有界分配。不是长期战略或所有可能分兵方式的全局最优。
- 使用空间索引查找邻近目标；空闲时约每秒重新评估，可执行任务完成库存同步后即准备下一轮，实际发射受扩张队列限速控制。覆盖扫描按设置进行。范围不变时复用仍活跃的订阅，不重复等待服务器加载同样的区域；新占领来源触发提前扫描，补足覆盖后加入，无需等待下个周期。同一同步计算片段内复用原生报价，让出主线程后刷新缓存，发射前重新读取并报价。
- 大量星球时仍让全部来源参与规划。距离排序只保留所需的前 K 项，其余三种排序每轮共享一次，与原有混合候选及补位结果一致；计算按约 8ms 的片段让出页面主线程，停止或切换模式会取消旧计算。覆盖查询保留已有分组，仅补新增网格，避免新占一颗星就重建大片订阅。
- 运行面板展示本轮已安排 / 总来源数和具备可行方案的来源数；可展开查看最多 6 颗未安排来源（可用兵力较多的在前），区分无预算、范围内没有目标、目标已在途、航时超限或分配给其他更快来源等原因。

### 无主星 2～3 星联合占领

每个目标混合选取最快和可抵达兵力最多的最多 6 颗来源，枚举 2～3 星组合。来源彼此距离最多 8，预计抵达时间相差最多 15 秒。分别计算每支舰队的损耗，最低抵达总兵力为无主驻军 +1+1；忽略己方 Assault 的正向加成，保持保守。

联合任务使用原生 `launchSwarmBulk({ kind: 0, targetId, launches })` 一次提交，计一次队列操作；任何来源失效则重新规划，不降级成多次单星发射。多支舰队仍分别战斗，目标在途中被他人占领会改变结果。敌方合兵尚未实现。

排队期间若一个来源产兵后已足够，可以改为一次完整的单星出征；复核时仍保护其他已规划目标的预算。这不涉及将失败的批量请求拆成单支重试。

## 集结进攻与据点推进

仅针对固定区域内符合敌人筛选的非盟友行星。比较目标产量、距离、发送量与实际航行时间，选择可承担的单星方案。基础报价由游戏提供，包含目标自然产兵与攻防科技；额外计入一个生产周期的保守防御余量和占领后留兵，再按边境损耗换算。

先对战区内全部可用来源做多目标直攻分配，仍按占点数、舰队数、收益和成本比较，并满足进攻的抵达截止时间；“近”由实际航时、搜索范围和资源需求共同决定，不只看坐标。随后用剩余预算为尚未安排直攻的目标选择集结计划，比较完成时间与所需兵力。直攻与补给都有任务时交替执行；集结等待期间继续直攻，任何来源的未预留余量仍可用于其他任务。

这是有界的两阶段优化：小规模直攻可求候选集内最优，集结在有限中转星 / 目标 / 来源中选取可行方案；不宣称包含未来生产、所有多步进攻和敌方行动的全局最优。

有任意其他舰队正飞往敌方目标时暂不进攻，以免把多场战斗误算成单次报价。当前不预测敌方未来发出的援军，不保证占领后永久守住，不攻击恒星、基地或黑洞，也不追击到战区之外。科技或其他必要情报接口缺失时停止；数百来源先集结到己方星球，真正攻敌仍由中转星单独发射，未实现直接多波攻打敌星。

### 大规模集结

- 初始中转星可在地图单选后读取，也可从区域己方星球目录按 ID / 坐标筛选。自动模式优先比较区域内有攻击路线的据点；中转星必须属于自己、位于战区内，且不能启用游戏原生自动升级 / 转发。
- 进攻兵力不足时，混合附近和高库存来源，最多比较 1,000 个来源；来源数不受扩张的 1～3 星限制。每批最多 50 个来源，通过原生批量接口补给己方中转星，与直接进攻共用 1 秒队列，不占扩张队列时隙。
- 只有预计总资源足以完成当前集结目标才启动募集。估算计入各段损耗、排队时间、集结等待期间的敌方增长、中转星的守军缺口与前线留兵比例；原生占领报价暂不可得时使用更保守的攻防/生产上界。
- 预留各来源具体数量，余量仍能参与其他任务。库存到账前不发起敌方进攻；实际出击再次使用原生报价和最新预算，不以在途承诺代替库存。
- 界面显示中转星、敌方目标、中转可用兵力、预计需求、补给在途和待募集来源数。发射统计包含补给舰队，占领统计只记录真正占领，不把给自己补兵计为占领。
- 中转星遭到来袭、归属或原生自动化状态变化时，不继续发出旧集结批次；目标战况改变则重新评估。每次集结有等待上限（补给最长航行 + 进攻时间范围 + 60 秒缓冲），超时释放未发射预留；已发舰队无法撤回。
- 开启据点推进时，确认攻下集结目标（或没有其他集结任务时从中转星发起的目标）后前移中转星。其他星球的独立直攻不打断正在进行的集结；关闭时保留初始选择。固定战区边界不变，旧中转星的余兵和已发补给仍可作为后续资源。

## 生命周期与验证边界

- 收起 / 切换 Tab 继续运行；后台暂停派兵，返回后重新扫描。刷新、断线、身份变化、页面缓存恢复不自动启动。
- 停止一个模式取消其未发射任务，不影响另一个模式。已经发射的舰队继续航行；等待中的发射确认和库存同步不会提前释放操作锁。全部停止或卸载后，等待两条队列的已发操作处理完毕再释放订阅。
- 发射确认不等于占领。后续扫描核实归属；在预计抵达后保留缓冲时间，不因缓存暂时看不到舰队而立即重发。
- 未知结果、超时或拒绝保守停止整个调度器，不自动重试。用户核对日志与在途舰队后明确解锁；迟到的成功确认只清除自己的标记，不重启任何模式。
- 各标签页共享一个 Web Lock，防止多个助手重复消费库存；扩张、进攻分别保存各自的限速记录；游戏原生手动操作不受助手队列控制。参数保存在 localStorage，ID 不转换为浮点数，不读取令牌或修改游戏缓存。
- 固定战区只加载区域及警戒 / 科技覆盖缓冲带，仍订阅己方资产用于核对结果。32×32 网格去重、每查询最多 24 格、最多 3 个并发，超过 2048 格停止并提示。

验证使用 Node/JSDOM 模拟世界和本地浏览器模拟页面，不代表真实游戏服务器已接受所有新订阅或成功完成进攻。游戏内部地图方法与数据表来自当前公开前端的只读核对；不为验证代码在真实账号派兵。
