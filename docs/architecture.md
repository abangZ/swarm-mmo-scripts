# 架构与开发约定

React 19、TypeScript、esbuild、pnpm。发布物为包含 React、React DOM、业务代码与 Shadow DOM 样式的单个 IIFE 油猴脚本。

历史功能与验证记录见 [history.md](history.md)，策略设想见 [strategy-research.md](strategy-research.md)，代码协作约束见 [AGENTS.md](../AGENTS.md)。

## 开发与构建

需要 Node.js 22+ 和 package.json 指定的 pnpm（当前为 10.34.5）。

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm dev  # 监听源码并重新构建
```

正式构建输出 `dist/swarm-mmo.user.js`，包含全部依赖，不依赖外部 CDN。脚本使用页面上下文（`@grant none`、`@sandbox raw`）。

Chrome / Edge 本地开发可安装构建时生成的 `dist/swarm-mmo-local.user.js`：在扩展管理中为 Tampermonkey 开启「允许访问文件网址」，将加载器完整内容粘贴为新脚本，并停用正式版以免重复加载。运行 `pnpm dev` 后，保存源码并刷新游戏即可加载更新；这不是页面热更新，刷新后仍需手动启动任务。

加载器的 `@require file:///...` 包含当前工程绝对路径，只供本机使用，不作为发布物上传。移动工程或修改匹配网址、权限后需重新构建并安装加载器。文件访问失败时检查路径、文件访问和扩展站点权限，参见 [Tampermonkey 本地编辑说明](https://www.tampermonkey.net/faq.php?q=Q402)。

## GitHub 发布

仓库为 https://github.com/abangZ/swarm-mmo-scripts，作者、主页与问题反馈地址统一配置在 `package.json`，由 `scripts/build.mjs` 写入油猴元数据。版本与 `GPL-3.0-only` 许可证标识同样取自 `package.json`。正式包包含版权、许可证与对应源码入口，第三方许可单独保存在根目录 `THIRD_PARTY_NOTICES.md`。

正式安装地址指向 `main` 分支的 `dist/swarm-mmo.user.js`，更新检查指向同目录的 `swarm-mmo.meta.js`。两者均由构建生成并纳入版本控制；发布时更新版本、运行 typecheck / test / build，再将源码和这两个生成文件一起提交，在获得推送授权后推送。不要提交 `pnpm dev` 生成的开发包。

本地加载器仍被忽略，`@downloadURL` 与 `@updateURL` 均为 `none`，防止油猴用远程正式包覆盖本地加载器。已有加载器需要重新安装一次才能获得该配置。

## 共享预算、独立队列

每个挂载只有一个 Commander 与一个执行用 GameWorld。扩张/进攻各有配置、running、queue、计数；共用跨标签页操作锁、扫描、已发射扣款和在途目标记录。协调器为每个模式维护一个出队任务和取消信号；扩张提交后即释放出队任务，回执与同步由 expansionObservers 在后台处理。进攻仍串行等待回执和同步。

预算：库存减去防守预留和未同步扣款。防守预留在重叠区域取更严格的固定下限/前线比例，再加已知敌方来袭的最大攻击上界。原生自动升级/转发来源排除。进攻的具体任务预留或有期限的攒兵计划再从扩张预算中扣除。发射准备在同一个同步步骤中预扣来源兵力、标记待同步来源和目标，另一队列出队时重新检查共享账本与最新进攻预留。攒兵最多 120 秒，超时冷却 60 秒，停止进攻立即释放。

`reserveFor` 对已知敌方舰队按 arrival 排序，每个前缀计算 `2 × 累计来袭兵力 + 2 − floor(max(0, ETA − 60 秒) / 60 秒) × level`，取各前缀与零的最大值，再加固定 / 前线守军。产兵只使用合法等级 1～10 的最低基础产量，保留一个完整生产周期的时间缓冲，不计科技、未来友军或盟友补给；缺失等级按零产量处理，缺失或非法来袭数量 / 时刻按不可出兵处理。逐前缀约束避免用最后一批抵达前的生产替第一批防守。

跨标签页 Web Lock 仍覆盖整个 Commander 会话，不由两个模式分别抢锁。扩张使用 `dispatchExpansion`，基准间隔加均匀 ±200ms 随机量，最短 1000ms；同一个发送时隙只抽样一次，失效队列项跳过时沿用该时隙，不重复抽样。进攻继续使用 `dispatch`，固定每秒最多一次。两个执行器共用按模式隔离的执行状态和 localStorage 时间戳，以实际调用原生接口的时间为基准，不补发错过的操作。扩张不创建未知结果标记，也不等原生 Promise；进攻仍保存 token 并等待确认。

覆盖扫描由独立 scanTask 执行；周期扫描保留扩张队列及正在等待限速的任务，只暂停下一次周期计时；成功后用 `scanPlans` 记录本轮仍待完成规划的活动模式。每个模式完整发布规划结果后移除标记，最后一个完成时设置 `nextScan = Date.now() + min(scanMs)` 并发布 nextScanAt。该节点位于 dispatch 之前，不等待发射回执、库存同步或整条操作队列耗尽。规划超过扫描间隔时也不重复触发周期扫描。`needsScan` 发现新增来源仍可提前补覆盖。

增加/停止模式会递增配置 revision，使正在分片计算或等待限速的旧方案失效，并在新的联合扫描完成后恢复调度。执行闭包再次读取真实库存、敌我关系、目标与在途状态。扩张只对本次任务的来源计算共享防守预算，扣除最新进攻预留，检查目标仍无主且在途摘要未变化，然后按原计划直接发射；不查询原生报价、航线或重做合兵分配。失效项跳过后可继续使用同一个发射时隙。扩张只在 coveredRevision 未追上配置 revision 时等待新覆盖；普通周期扫描不阻塞已有扩张队列。进攻仍在扫描期间暂停其实际发射。任何来源丢失或库存不足均取消该未发射任务。inventoryRevision 记录并行发射和同步；扩张算出空计划时，若期间库存版本变化则立即重新评估，避免对已经释放的来源再空等一秒。

进攻在 `OffensivePlanner.fork()` 副本上经 `runPlanning` 执行直攻和各据点的生成器。分片恢复同时校验配置 / 库存版本、运行状态与订阅；只有完整且仍有效的结果才替换主规划器和预留。并行发射、同步、占领确认和预留变化都会使库存版本变化，过期草案不能覆盖新据点状态。进攻首次成功扫描调用 `attackStartupIssue`，无来源 / 全部原生自动化时删除进攻配置并发布明确错误，下一轮重新确认扩张覆盖，不全局 fail。

停止一个模式保持另一个模式运行；已提交请求的账本与目标锁继续属于协调器，不能因停止某个 Tab 清除。全部停止后取消未发射任务，等待出队任务、扩张后台观察和正在进行的库存恢复完成有限清理，再释放操作锁和世界订阅；扩张观察分别用 within 限制回执 15 秒、同步 12 秒。迟到的 Promise 成功 / 拒绝已有处理器，但不再次修改已结束观察的状态，不自动重启。

## 扩张后台计算

扩张拥有独立 planningTask，不占用出队任务。周期扫描完成或队列剩余长度接近 `max(3, min(20, ceil(上轮评估耗时 / interval) + 3))` 时开始补充；首次启动没有旧队列时，前线小批规划可在完整首轮结束前提供任务。规划快照先锁定已有队列目标并扣除其数量预算，因此新候选只使用剩余资源。发布前读取最新内存库存，合并仍未发出的旧项和新项，过滤已发目标、舰队摘要变化与预算不足的项；不重复扣除已经同步到缓存的发射。配置变化、停止和恢复会取消计算并关闭生成器；收尾等待扫描、规划与已发任务后释放世界适配器。

游戏 `www.swarm-mmo.com/play` 的 CSP 未配置 `worker-src`，回退到不含 `blob:` 的 `script-src`。因此页面上下文中的 Blob Worker 会加载失败，Chrome 的 error 事件可能没有 message；v0.14.0 将此误当成连接异常，反复重新扫描。

v0.14.1 移除 Blob Worker 和消息桥接，复用 `expansionProposalSteps` / `expansionPlanSteps` 在主线程协作分片。约 8ms 后通过 `scheduler.postTask(..., { priority: 'background' })` 续跑，避免默认优先级的 `scheduler.yield()` 延迟发射计时器。每次原生内存报价前都检查分片预算，恢复时校验当前配置、取消信号与规划版本，再刷新报价缓存。恒星 / 陨石与升级使用相同调度方式；所有数据来自已有内存和必要订阅，不增加网络接口。停止或配置变化后丢弃草案，发布前仍校验最新预算并合并旧队列。这里是异步协作调度，不是独立后台线程。

保留一个全局规划任务，增加一个有界的前线增量草案，不引入 Worker 池、Service Worker、油猴跨沙箱桥接或旧浏览器兼容层。发布物仍为单个 JS；用户无需关闭 CSP 或修改 Chrome 安全设置。

设计依据：[worker-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/worker-src) 的 CSP 回退规则；[scheduler.postTask](https://developer.mozilla.org/en-US/docs/Web/API/Scheduler/postTask) 提供后台优先级调度。

验证：Node 假时钟覆盖慢扫描期间连续发射、慢规划结果与实时库存合并、停止取消和旧结果丢弃，并覆盖慢规划期间恒星仍可发布及发射、库存 / 归属 / 驻军变化后的恒星预留释放。1,311 来源 / 566 目标的分片规划与同步算法逐项比较提案和分配，确认全部来源保留、bigint ID 完整、原生报价调用数量不增加；慢原生报价后取消不会继续读取报价或发布草案。浏览器验证使用与游戏相同的 CSP 和模拟内存数据，不在真实账号派兵。

Linux Chrome 156.0.8078.79 的独立 headless 实例复现了 CSP 阻止 Blob Worker、error.message 为空的行为。修复后 1,466 来源 / 566 目标正常评估约 0.4 / 0.3 秒，19 秒提交 16 次模拟发射；人为增加报价耗时使第二轮评估达到 6.0 秒，28 秒仍提交 23 次，间隔 1.05～1.39 秒。5 秒扫描期间继续发射 4 次，无重复目标、CSP 违规或超过 50ms 的长任务。这些数据仅验证调度与规划，不代表真实游戏报价耗时或 24 小时挂机验收。

### 前线增量响应与当前工作状态

`FrontierPlanner` 与全局 planningTask 独立推进，但只向同一个扩张队列发布任务，不增加执行器或发射频率。约每秒读取活动订阅库存；相比上次检查增加至少 `max(20, 原库存的 10%)` 的来源优先检查。首次覆盖完成后超过 2 秒、或队列不足 3 个非升级任务时，轮询距离上次检查至少 5 秒的来源，优先检查最久未检查的来源，时间相同时兵力多的优先，防止反复检查无可行航路的大兵源。先按攻击加成上界排除明显无法单星完成的邻居，再截取最近 32 个；跳过没有可能目标的来源，不消耗 4 来源报价额度。每批最多对 4 个来源报价，首个有效来源选出最多 3 个目标后立即发布；无附近目标的后方来源只做空间查询。小额增长及合兵机会仍由完整规划处理。

前线规划复用独立的 `PlanningQuotes` 缓存，保留原生报价及安全余量，检查风险、固定战区、在途舰队与目标锁。计算和发布均扣除共享防守、进攻、恒星预留和已有占领任务；发布重新检查当前身份、报价版本、目标内容、舰队摘要与库存。新机会与保留任务按航时排序（恒星任务仍优先），不重分配已有合兵；新占领任务替换未发出的升级项，避免升级占满队列窗口和预算。停止、配置变更和重连取消前线草案，清理等待它结束后才释放世界适配器。

`ExpansionState.work` 单独维护扫描、规划阶段 / 开始时间 / 来源进度、前线计算、发射等待、后台回执与库存重试数量。最近事件继续写入 phase 和日志，不能覆盖真实工作状态。进度通知每 250ms 最多一次，来源阶段完成时补一次；计时由 UI 每秒更新并在停止 / 卸载时释放计时器。未完成全局规划时明确显示扫描倒计时将在规划后开始，不展示含义不明的空值。

模拟测试覆盖全局草案挂起时补兵在下一次 1 秒检查中触发附近派兵、进攻预留及同源预算不超支、停止取消前线草案、420 来源慢规划期间两个模式各自限速、旧升级事件不遮盖规划阶段和计时。此响应时间是 Node 假时钟下的调度验证，不是实服报价延迟保证。

## 情报与策略边界

固定区域约束来源和目标，中心与半径以启动时的配置快照为准。进攻必须指定区域；扩张可选择全部领地以兼容旧行为。区域订阅包含警戒和科技覆盖缓冲带；不围绕区域外大量己方资产扩张空间订阅。

订阅内容包括己方星球与舰队、区域星球、所有飞向区域的舰队、附近恒星/基地、联盟与科技、己方原生自动化，以及区域玩家名字。先等待订阅确认才计算，失败整体停止。区域预览使用独立的短期只读 World，不获取操作锁、不派兵；编辑区域或卸载时旧响应失效，最终释放订阅。

`GameWorld` 按查询字符串保存长期订阅，通过 `subscriptionBatches` 保留既有网格和玩家 ID 分组，每组最多 24 项；删除不再需要的项，新增项先填已有分组空位，再建新组。完整分组保持查询不变，增长只影响尾组/空位，不全局重新排序分块。批次总数受历史覆盖规模上界约束，不随扫描次数增长。复用相同的活跃句柄，只增补缺失查询、释放不再需要的查询。只有扫描成功才发布新分组；扫描取消只回收本轮新建句柄，已持有句柄和原分组留到下一轮或最终清理；失效订阅或断线先停止出队，再按模式执行恢复或停止。`needsScan` 检出战区内新增来源时提前补覆盖，全领地模式也无需等待扫描周期。`read` 和每次计算分片恢复时的 `refreshQuotes` 校验连接、订阅并清空原生报价缓存，`quote` / `route` 仅在同一个同步片段内复用结果，出队重新 `read`。扩张保留规划结果中的发送数量与分配，不再调用报价；进攻仍使用出队快照的新报价。

敌方星球只使用单星原生报价，追加生产时点误差与占领守军，并按航行损耗转换；有其他舰队在途则跳过。尚未实现直接多波攻敌、跨战区追击、敌方恒星或基地战斗。扩张可占无主恒星与陨石。不把公开前端报价当成完整的服务器战斗模拟。

无主星允许 2～10 来源 native bulk，maxSources 数字输入范围 1～10、默认 3，设为 1 禁用协同。配置、UI 和分配器共用 maxCoalitionSources 上限。安全余量统一为 `captureMargin = 1`，规划阶段的单星报价与合兵抵达需求均使用此常量。已存在外部己方舰队时，仅在同星系到达兵力、时间和归属均可证明时按缺口补兵；未知损耗、其他玩家竞争或已有助手目标锁继续等待。排队时目标在途摘要发生变化则跳过该项，不沿用过期的缺口补兵判断。

进攻使用原有 debits / pendingSources 屏障；扩张使用 expansionStock 保存每个来源的本地剩余库存上限，并用 expansionPending 计数同来源尚未完成后台处理的请求。每次扩张发送前从 min(实时库存, 既有上限) 扣本次数量；共享预算基于该上限计算防守与预留，允许余量连续发送，避免再从已更新的游戏库存扣同一笔。较早请求同步成功后，只有同来源所有后台请求均结束才移除上限。同步失败或还有较新请求时保留上限并记录 inventoryDirty；无待处理请求的脏来源每 5 秒最多重试一批 24 个 ID 的短期订阅，不重试发射。旧模拟适配器无 syncInventory 时仍在扫描屏障释放已结束请求的上限。

扩张原生请求提交时即增加 sent 并锁定目标；这只表示提交，不表示服务器成功。目标初始保护到 max(60 秒, 航时 + 15 秒)，收到及时成功回执后改用确认时间加航时；扫描再加 5 秒缓冲，没有占领或在途证据才释放。回执超时 / 拒绝只日志说明跳过，后台继续同步库存，不直接重试同一任务；后续扫描可重新规划仍可用的目标。占领计数始终取扫描归属。

unresolved 忽略旧 expansion 和旧版单 token，withControl 在独占 Web Lock 内清除它们；不会在另一个标签页运行时清理其状态。进攻未知 token 仍使两种模式停止并要求核对，迟到的进攻成功回执只清除自己的 token。扩张不持久化运行状态，刷新后仍需用户手动启动并重新扫描。

扩张允许隐藏标签页运行，进攻隐藏时不参与出队和本轮规划倒计时屏障。连接 / 订阅 / 扫描错误进入 5 秒恢复等待，取消旧未发射任务、停止同时运行的进攻，等已有请求的有限清理后释放旧 GameWorld，再建立新 World 和完整覆盖；首次成功快照绑定 identity，重连身份不同则停止。显式停止、卸载、刷新或身份变化不会自动重启。页面冻结、浏览器后台计时器降频和系统休眠不在脚本的控制范围内。

## 扩张策略、特殊目标与升级

批量升级接口证据：2026-11-03 只读检查[游戏客户端](https://www.swarm-mmo.com/assets/index-C97C76VC.js)，原生 reducer 为 `upgrade_planets_bulk`，参数是 `planetIds: u64[]`；多选升级入口使用 `upgradePlanetsBulk` 并按 200 颗分片。未调用真实账号升级。

`Assignment.targetKind` 缺省为 planet，另外支持 sun / comet。原生 ID 始终是 bigint；全局在途锁、队列分组、报价缓存和 React key 使用 `kind:id`，避免不同表相同数字 ID 冲突。旧进攻规划器通过 planetLocks 只取得行星锁。GameWorld 读取 sun2 / meteorite2 表并建立 bodyFleets 索引；恒星来袭同时检查 swarm.targetSunId 和 sun_swarm2，陨石检查 swarm.targetMeteoriteId。按设置增补区域 meteorite2 / sun_swarm2 订阅并沿用稳定分组与清理。Meteorite 是行类型名，连接属性与 SQL 表名均为 meteorite2，不能从行类型推导表名。仅开进攻时不加载这些额外表。

`LogisticsPlanner` 为行星前线与恒星各保留一个活动计划，独立于全局规划约每秒检查游戏内存。发现阶段用空间索引选每颗来源最近两个目标，每次最多考察 16 对，保留轮询游标。已有目标有效时继续推进，不重新选址；该有界策略不宣称全局最优。普通扩张仍保留全部来源与原候选范围。

后方来源不再受直接合兵的距离 8 / maxSources 上限约束，仍遵守固定战区、最长航程、原生自动化排除、共享防守与进攻预算。每类计划每次最多新增 128 次原生航路计算，逐项让出分片；纯航路缓存按规则版本、两端位置 / 星系 / 所有权验证，有效结果保留 10 分钟、无航路 10 秒。兵力变化重算缺口与分配，不清空纯几何缓存；取消草案可以保留纯缓存，不发布半成品预留。

目标可由当前总预算及已知在途完成时，按航时分配补给，每批最多 50 颗来源，通过原生批量接口发射，即使只有一颗来源也不降级接口。只预留据点和本批具体数量，剩余来源仍可供其他任务使用。发射后记录来源 / 数量 / ETA / 损耗，按这些字段与内存舰队一对一去重；未知外来补给暂停追加。每批后更新剩余缺口，目标与据点持续保留；补给与普通占领交替进入同一个限速执行器，实际到账后才允许原生单星占领报价出击。附近新增廉价目标可先从据点出击，不撤销昂贵目标。配置、归属、目标、库存和规则变化在发布与出队重新验证；停止 / 恢复丢弃计划，已发舰队不会撤回。

前线升级只考虑 1→2：稳定观察后，比较继续攒兵 / 补给与支付 100 费用后升级的占领 ETA，计入抵达前缀、生产和批次排队。缺少当前原生占领价时，对不升级方案采用科技攻击上界的乐观费用，对升级采用保守费用，只有后者仍更快才升级。无邻敌、无来袭、无便宜可占目标、当前真实库存可支付、回本在收益周期内且后方航路检查完整才入队；发射前输入指纹变化使该决定失效。`ProductionTicks` 只读 SDK 科技与覆盖：基础每周期产量为等级，周期 60000ms；己方 / 盟友恒星半径 8 或有效基地半径 min(level,10) 内使用 floor(60000 / (1 + 0.005 × construction))。预测只用于比较，不能进入可用库存。

普通行星使用占点优先分配器；陨石由独立有界快速检查补入同一扩张队列。陨石原生类型 comet、表 meteorite2、接口 launchSwarmAtMeteorite；按实际排队位置和出队航时检查到期，抵达至少早 5 秒。后勤预留从两个模式预算扣除，原有队列继续发射；新批次超出队列窗口时释放该批捐兵预留，下次增量推进。

普通行星收益使用独立 economicHorizonMs（默认 3 小时），不再使用派兵窗口。cautiousExpansion 默认 0，保持快速占点；开启后仅基于已观测敌我地理关系排除孤立暴露目标，不声称估计敌方 ETA、反击概率或全局战略最优。两种取向均保持动态防守预算。

风险评估的己方支援搜索至少覆盖 8 格，不随更小的敌情警戒半径缩减。

StableUpgrades 记录连续安全观察时间（默认 10 分钟）；固定战区、敌方警戒、来袭、原生自动化、附近无主机会和具体任务预留均限制升级。每轮最多追加 200 个单级升级到占点队列之后，使用 `upgradePlanetsBulk({ planetIds: bigint[] })` 原生批量接口；批次上限与游戏客户端的 200 颗分片一致。排队窗口按每批一个操作时隙计算，占点任务仍优先于整批升级。出队在同一快照逐颗过滤失效项，预扣所有有效来源的库存后一次提交，不降级或拆分失败批次。费用按未折扣 100L² 上界预扣，基础回本须不超过收益周期，实际同步后释放上界。出队再核对原等级和所有保护条件；已尝试的同一等级不会因迟到回执或未知结果重复提交。每批只建立一个后台观察任务和一次逻辑库存同步（适配器仍按 24 来源拆订阅），日志按批汇总。批量请求回执不等于全部升级成功，同步后仅统计仍为己方且等级高于预期原等级的来源；未确认项不重发。升级不计舰队或占领，不启用永久服务器自动化。停止、重连或重新启动重置稳定观察。

ExpansionJournal 仅记录本次会话，统计提交兵力、确认占领类型、占领时基础产量和确认升级；最多跟踪 1,000 个未完成观察的占领，计算 30 / 60 分钟持续保有。陨石不进入保有率，曾观测到失去所有权的目标即使重新夺回也不算持续保有；不能证明两次扫描之间或断线期间没有短暂失守。UI 的本轮选择原因最多 5 条，独立于每模式 50 条活动日志。

## 大规模己方集结

`OffensivePlanner` 持有 1～3 个独立 `RallyPlanner` 据点（默认 3，指定 rallyId 时为 1），各自保存集结目标、期限与前移状态。目标战斗依旧是单星；大规模来源只向己方中转星增援。固定战区约束所有来源、中转星和敌方目标。

每轮先让 `attackPlanSteps` 对全部来源生成直攻候选，复用有界分配器求多目标计划，再将每个直攻的数量从预算扣除，剩余预算依次交给各据点。通过 usedHubs / excluded 排除重复据点和已安排目标，各据点只预留具体数量。`rallyId` 不限制直攻来源。`OffensivePlan.jobs` 交替放入直攻和补给，补给按上次实际执行据点轮转；合并队列仍受 horizonMs / 1 秒的容量限制，被补给挤出窗口的直攻释放预留。补给预计排队按据点数以及直攻交替保守计入，不为扩张占用时隙乘以 2。

自动选址对所有候选据点分片检查到敌方的可行航路，再混合最快 4 个和库存最多 4 个据点，各自比较最多 3 个目标的完整募集方案；比较集结等待加进攻航行的总抵达时间，再比较所需兵力。有已知敌方来袭的据点不参与。不可行 / 超时路线不会在按库存截取时挤掉前沿据点；使用集结或混合队列时不宣称全局精确最优。

每轮填充空闲 / 前移据点之前，先读取所有仍有效 campaign 的据点和目标占用，再把其他 campaign 的占用传入本据点的候选排除集合，避免较早的规划槽抢走后续已筹兵任务。这不排除直攻，也不锁定补给来源的剩余兵力；据点失去归属、离开战区、启用原生自动化、目标失效或任务过期时不保留占用。

`Assignment.kind = reinforce` 区分补给与占领。单个补给批次最多 50 个来源，不经过扩张规划器的 10 来源约束；集结计划混合最多 1,000 来源，为全部待用贡献预留具体库存。批次只占一次进攻队列操作，停止或失效时不拆成单支重试。同一个来源的未预留余量可以继续用于其他任务。

集结需求计入等待期间的敌方生产、敌方报价/保守上界、各段损耗、队列时间，以及中转星的动态留兵比例和已有守军缺口。当前在途与本地确认记录合并去重；本地按每支补给的预计到达时间记录，不将已经到期的承诺再加到实际库存。这些预测只决定募集量，实际出击必须由真实已到账库存通过最新报价检查。

集结补给单独记录，不能加入占领目标锁并把己方中转误计为 captured。新的订阅确认与到达缓冲清理补给跟踪。`launched` 只清除同目标的集结任务；独立直攻不清除另一个集结。记录需要前移的主攻目标，只有其后续占领确认才触发对应据点前移，不影响其他据点；独立直攻占点不打断活动集结。前移不重写战区中心，用户可关闭。中转有敌军来袭、丢失归属、启用原生自动化或已足够出击时，取消排队中的旧补给批次。

`rallyId` 以十进制字符串持久化，再转换 bigint；`rallyMinutes` 单独控制补给航行，默认 30 分钟；旧表单补入 rallyHubs = 3，不改变已存区域 / 敌人。阶段状态展示每个中转与敌方目标、实际可用库存、预计需求和在途补给。短期自然攒兵与大规模集结是不同策略：前者最多 120 秒，后者有最长补给航行 + 进攻最长航行 + 队列窗口 + 60 秒的期限。

## 候选与性能

每颗来源最多 n 个候选，锁定/不可补兵目标在截取前排除。先保留最近 max(32, 8n) 个目标及原有混合样本，按距离检查。找到 n 个可行单星就停止；根据攻击上界明确只能合兵的目标，取得 n 条有效近程合兵航路后停止额外原生报价，仍继续廉价检查样本中的单星机会。无效或超航时路线不占合兵额度；已有舰队的缺口补兵仍走原生报价。禁止先交错抽样、再因已有 n 个远处可行目标提前结束，导致更近的可行目标从未被报价。剩余槽位供合兵候选使用；预算为零的来源不查询报价。

`WorldSnapshot.attackMultiplierUpperBound` 来自适配器读取的当前己方 Assault 科技（原生倍率 1 + 0.01 × assault），乐观假定来源都处于科技覆盖。提案阶段对来源及 8 格内最多 maxSources - 1 个最强可协同来源逐项向上取整后求和；即使忽略损耗、抵达时差与其他可行性限制仍不能战胜驻军时，省去该路线的原生报价。已有舰队的目标不走此裁剪，缺失科技上界则禁用；它不是发射数量公式，实际可行方案仍由原生报价与现有合兵验证决定。

`PlanningQuotes` 仅缓存扩张的无主行星 / 恒星 / 陨石报价与航线（含暂时兵力不足的结果）。来源几何 / 归属 / 等级和目标行作为成功报价的局部依赖；失败报价另比较来源库存及更新时间，增兵后重试。已成功的无主报价不因自然产兵而失效，当前预算仍独立核验；`GameWorld.read` 提供 quoteVersion，覆盖身份、科技、联盟、星系几何和恒星 / 基地覆盖。基地 superprobes 是否大于零决定覆盖是否有效，正数之间的库存变化不影响覆盖；目标自身驻军仍按局部依赖比较。SDK Identity / Timestamp 按实际值、bigint 按完整值比较。没有版本支持的适配器不复用，敌方和己方目标始终走新报价；上限 100,000 条、10 分钟，未知航线 5 秒重试。底层每次分片仍刷新连接和同步报价缓存，独立的规划缓存仅复用依赖匹配的记录。来源库存变化仅在需要单星报价时重算失败结果；纯合兵航路不依赖库存，继续复用有效几何。目标变化重算相应报价；停止或恢复清空缓存。GameWorld 同时提供 quoteGlobalVersion（本实例内的身份 / 自身科技 / 星系几何版本）和 sourceQuoteVersions（上述版本加来源归属、位置、等级与友方影响覆盖布尔值）。覆盖判断复用 ProductionTicks 的原生影响范围模型：恒星半径 8、有效基地半径 min(level, 10)。远处基地或联盟变化但来源仍处于相同覆盖状态时，继续复用其报价。发布与出队按任务全部来源检查 quoteRules；只释放受影响任务，草案过滤失效候选后继续完成。旧适配器缺少局部版本时保守回退到 quoteVersion。

报价缓存不缓存分配结果：每轮仍重新读取在途锁、可证明补兵缺口、共享库存与防守预算，在现有队列基础上补充任务。预计算阈值由历史耗时估计，但上限 20 项，避免一次慢规划让后续每个 tick 都重算整个队列。日志额外输出新算 / 复用路线报价数。

`bestCandidates` 用稳定最大堆保留距离排序的前 `max(32, 8n)` 项；驻军、单位产量和附近机会三种与来源无关的排序只对可达目标并集计算一次，再按各来源距离过滤。`PlanetIndex.ordered` 保留与 `near` 相同的网格和插入顺序，确保平局与完整逐来源排序相同。附近机会预计算也设置分片点。仍遍历全部来源、完整邻域，不减少 n、搜索距离或可行目标补位数量。距离排名及空间范围筛选使用距离平方。

`expansionProposalSteps` / `expansionPlanSteps` 和进攻规划均使用生成器；原同步函数仅供算法测试与同步调用。Commander 通过 `runPlanning` 每约 8ms 让出主线程，并以 background 优先级续跑；来源、每项原生报价、合兵目标、据点、补给来源和分配搜索均有检查点。这是协作调度预算，不是每个片段的硬耗时保证。每次分片恢复检查配置 revision 和运行状态；进攻还检查页面可见性，旧计算取消后关闭生成器；报价阶段恢复还须校验连接/订阅。两条队列使用同一份共享库存、进攻预留与在途锁，不能各自分配完整库存。

两种模式均将 `maxTravelMs`（默认 30 分钟）作为独立航程上限；`horizonMs` 仅限制队列预计发出时间。`planExpansion` 第五个参数启用此语义：占点数之后先比较总占领耗时（合兵取最后抵达时间），再比较舰队数、收益与成本，并按短航程先发。省略第五个参数时仅保留旧调用者的截止时间 / 收益优先语义，当前运行模式均显式传入上限。保留能增加占点数的合兵方案；相同占点数与抵达时间时优先单星，避免平局时不必要的拆兵。2～3 来源保留最多 6 颗候选枚举；更大协同通过 cooperationGroups 混合最快 / 最强最多 2 × maxSources 颗来源，逐步形成满足两两距离与抵达时差的组，最多输出 32 个大组，组间让出计算。coalitionOptions 对大组最多使用 4 种分配顺序 × 2 种分配方式。扩张出队保留原计划，不重新优化为单星。

小规模搜索最多 20,000 节点；大规模裁剪为最多 128 个目标、每目标 8 个方案，界面明确显示有界优化。不是全地图或未来多步战略最优。扩张独立消费旧队列，周期扫描或临近耗尽时后台补充；空闲时约每秒从活动订阅重新评估。进攻在两次扫描之间复用混合直攻 / 补给队列，不在每次发射后重做全战区规划，队列耗尽或新扫描再规划。进攻出队仍刷新报价，扣除其他任务预留后检查本项可用兵力；发射用实际数量扣款，但释放原计划分配，失效项也释放本项分配。新增来源提前触发覆盖扫描。提案同时返回各来源可用预算与阻塞原因，Commander 汇总已分配来源并保留最多 6 颗未分配来源供 UI 查看，不将这些诊断当作兵力预留。

## 内存复用与耗时观测

普通提案以配置、库存、目标、锁、舰队、自动化、身份和报价规则指纹复用；完全不变时复用整份结果（无舰队最长 30 秒，有舰队 1 秒）。变化时仍由逐路线报价缓存复用无关部分。后勤单独保留活动目标和纯航路，草案发布核对计划版本，自己的发射会使旧草案失效。

GameWorld 的读取、生产预测及原生 quoteSend 均访问已有内存，不新增规划订阅。覆盖扫描复用有效查询，仅新增范围补订阅；发射后的临时库存查询作为确认屏障保留，避免过期内存重复花费。diagnostics 分别记录最近 read / scan / sync 耗时、扫描新增与复用订阅，以及累计原生内存报价次数和耗时。UI 展示后勤阶段、募集缺口、来源检查数、预测占领时间和新算 / 复用航路数。

模拟验证覆盖 6,001 颗己方来源的冷航路分片、无变化及仅库存变化时零新增航路调用，130 来源分 50 / 50 / 20 批持续募集，以及真实库存到账前不攻目标。该测试不代表实服端到端延迟，也未在真实账号发射或升级。

设置项的详细说明收纳在对应标题旁的问号提示中，支持悬停、点击或键盘聚焦查看，Esc 关闭。操作间隔、队列窗口、航行时间、恒星 / 陨石和升级说明分别绑定各自字段；问号与复选框标签分离，查看提示不会切换设置。

前线短周期检查作为后台监测展示，不覆盖主动作与状态徽标；运行时保留固定的前线监测行，持续超过 2 秒的检查才显示耗时，避免短任务反复插入 / 移除内容造成面板抖动。停止与异常仍立即显示。

## v0.15.1 规划延迟分解

`runPlanning` 分别记录生成器计算、调度等待和分片恢复检查耗时；正在等待的片段也计入界面。全量规划继续使用 background 优先级，前线与后勤使用普通计时器续片，避免等待繁忙页面的后台任务调度，同时保留派兵计时器执行机会。同步原生调用无法中途抢占，单次慢报价仍可能阻塞主线程；界面记录其平均、最大耗时及超过 8ms 的次数，不将全部墙钟时间归因于网络。

只读检查官方客户端已有实现：quoteSend 同步调用航路与精确报价，内部再次计算来源航路；没有等待网络的代码。适配器同片 route / quote 共用一次原生调用；跨轮成功无主报价复用库存无关的占领要求，来源几何、等级、归属及规则变化仍失效。未修改游戏方法或缓存。SDK 内存读取额外记录 listOwnedBodies 遍历耗时、累计快照次数；syncInventory 分别记录批次、实际订阅次数、在途批次和累计耗时，并保留确认屏障。

新增模拟回归覆盖后台任务永不恢复且前线报价每次耗时 10ms 时仍能发布与派兵、32 个不可打近邻之后的可打目标、25 个来源轮询饥饿、成功 / 失败报价在库存变化后的不同失效边界，以及计算 / 调度 / 网络订阅计时分离。当前没有实服 272 秒那一轮的计时采样，不能据此断言其主要耗时类别。

## v0.15.2 实测报价放大与完成屏障

2026-11-03 在 v0.15.1 实服页面只读展开诊断：3676 来源的全量规划第 432 秒，进度 1547；compute 258705ms、wait 173704ms、refresh 804ms、28347 次分片。累计 native quoteSend 118260 次 / 261765ms（平均约 2ms、最慢 34ms）。初始覆盖 61 个新增订阅耗时 29912ms；库存确认 74 批 / 74 个订阅累计 36521ms，当前无等待批次。后者后台并发，不能相加为全量规划的等待时间。此样本确认报价量而非单次网络查询是主要放大项。

原候选停止条件只统计 affordable 单星数量。典型弱来源即使保留 n=10 个合兵候选，也会把 80 个以上目标送入原生报价。现在用 optimistic solo power 标识仅合兵候选，对这部分单独计数有效航路至 n，再继续原样本的单星机会检查。所有来源、固定战区及搜索半径保留，2～3 来源枚举和 4～10 来源有界组合不变；只对尚未报价的合兵候选采用近邻优先上限，不宣称全域最快合兵路线。

PlanningQuotes 的 route 读取独立比较来源规则 / 几何与目标依赖；即使旧单星报价失败，也能在库存变化后复用航路。随后 quote 请求仍按最新库存重算失败价格，增兵到能单星出击时不会被旧 null 阻挡。报价安全余量、科技版本失效和发射预算核验保留。3676 来源 / 160 目标 / n=10 / 最多 5 来源合兵的模拟回归首次 36760 次报价评估，旧路径至少 294080 次；全体自然产兵后的下一次新增报价为 0，单个来源补足后单星报价正常恢复。

发现新来源时的补覆盖扫描可与全量提案并行，不受 planningTask / scanPlans 屏障阻挡；普通周期扫描仍从规划完成后计时。前线内存检查同时核实占领和在途锁，避免已占领统计停在零。reconcile 的库存屏障明确区分：只有正式同步 / 扫描能释放旧适配器账本，单纯内存观察不能提前释放扣款。回归覆盖全量草案挂起时新来源覆盖及占领计数推进，并继续验证两个模式预算不会重复使用。

## v0.15.3 有界续查与调度等待

v0.15.2 实服同轮两次只读采样：110 秒检查 1108/3733 来源，159 秒检查 1316/3733 来源。后一个测点 compute 77678ms、wait 81563ms、refresh 300ms；累计原生报价 31424 次 / 81626ms，最新覆盖 55ms（0 新增 / 61 复用）、库存同步当前 0 个等待批次。相对 v0.15.1 测点，累计来源吞吐约 2.31 倍，但后段 49 秒只推进 208 来源。场景及累计计时范围不同，不作为严格完整轮次基准。剩余慢路径是 optimistic solo 上界通过、实际报价不可行，仍试完 8n+ 候选；调度等待占计算与等待合计约 51%。

BackgroundPlanner 持有 CandidateSearch。每颗来源只保存下一目标 ID / 位置、至多 n 个候选 ID、来源规则与兵力观察基线，不持有可直接发射的旧报价。首轮至多 n 次评估；续轮复核至多 n 个保留候选，并允许至多 n 次其他评估，包括失败报价 / 航路。两个最近邻（n=1 时不占用续查槽位）优先复核，其余沿游标前进。候选仍来自原近邻与混合样本，不缩小来源集合、半径或固定战区。完整可行短名单仍可复用，不因自然产兵额外扩展报价；未查完时禁止整份提案缓存阻止续查。

自然产兵不重置游标；相对观察基线增兵达到 max(20, 10%)，或者位置、等级、归属、规则版本、配置变化时重新优先检查近邻。选中的候选每轮重新经过当前目标所有权、在途、库存、报价缓存失效规则和协同约束。游标在草案副本中推进，仅当前有效结果完成后发布；取消不推进位置，停止 / 恢复清除状态，删除的来源随下一轮清理。同步算法入口仍保留完整样本搜索，供对照和算法测试；实际 Commander 使用有界后台入口。

全局规划 runPlanning 从 8ms 起步，后续预算为 min(12ms, 8ms + 上次调度等待 / 2)。保持 background 优先级，每片继续复核运行状态并刷新原生缓存；前线、后勤和进攻没有扩大时间片。单个原生调用不能抢占，预算不是硬实时上限。确定性时钟回归验证等待减少、首次让出和 12ms 预算，既有实时时钟测试继续验证发射计时器可运行。

3676 来源 / 160 目标 / n=10、预估可打而原生单星报价均失败的模拟中，首轮报价评估由 398300 次降到 36760 次（约减少 90.8%）；剩余候选在后续轮次继续检查，不代表整个搜索的总工作量消失，也不代表实服墙钟同比提速。另覆盖 n=1、游标目标删除、明显增兵、自然产兵、易主 / 在途失效、草案取消，以及有效短名单零新增报价复用。未改变库存同步确认屏障，未在真实账号发射或升级。

## v0.15.4 前线合兵与补覆盖计时

原 FrontierPlanner 只检查单星预算，合兵依赖完整 proposals 完成，因此附近几颗来源合计足够、单颗不足时，快速通道不会产出任务。前线现在用来源与最多允许数量邻居的攻击上界筛选，再对有界近邻进行原生航路验证和已有 cooperationGroups / coalitionOptions 计算。每个锚点至多检查 4 个合兵目标、最多 20 个邻居，整次快速检查至多 96 次来源报价或航路评估；继续按 8ms 定时器分片，首个有效锚点即返回，最多三个任务。没有附近目标时不搜索合兵来源。单星可行优先少用舰队；现有 2～3 来源枚举、4～10 来源有界组合及来源距离 / 抵达时差 / 损耗约束保持不变。

草案在本地扣除全部成员的具体数量，多个目标不重复使用支援星兵力。updateFrontier 发布时再次核验所有成员所有权与剩余共享预算，不能仅核验主来源；执行仍通过原独立队列及 launchGroup 批量接口。模拟覆盖 435+230 占领 644 驻军、全局草案未完成时合兵可派出、在途不重复、支援来源库存变化拒绝整批，以及数量、损耗、距离和抵达时差限制。此处未声称截图中目标的原生航路已实服验证。

Commander.scan 增加 coverageOnly：已有配置覆盖生效、但发现新增来源且周期扫描未到期 / 正在规划时，只补覆盖。它更新库存与来源数，但不清空 scanPlans、不把 nextScan / nextScanAt 改成未计时，也不强制安排新的全局草案；前线可使用新来源。即使全局规划在补覆盖请求期间完成，其倒计时也不会在请求返回时被清除。初次启动、配置变更及真正到期的周期扫描仍走完整扫描和规划后计时规则。日志分别描述周期扫描与补覆盖。

quoteVersion 对科技、联盟、基地、恒星和星系行先生成排序稳定的指纹；SDK 迭代顺序变化不再伪装成规则变更。真实字段变化仍失效，不写游戏缓存。全局结果因真实报价规则变化丢弃时增加明确日志，避免无说明地回到进度零。只读浏览器采样确认当前仍运行 v0.15.2，日志中既有新占领后密集补覆盖，也有 1.4～5 秒完成的暖缓存规划，不能把每次回零都解释为中途取消。


## v0.15.5 独立陨石通道与局部失效

Commander 持有独立 MeteoriteFrontier、报价缓存、取消信号及约 1 秒检查时钟，覆盖就绪后与全局规划并行。每批最多 8 个目标、每目标 4 个来源、3 个任务，使用 8ms 定时器分片；目标按到期时间排序轮转，最近来源复查，其余来源游标持续推进。没有可用来源、已有锁、寿命不足等条件在原生报价前排除。预算按防守、本地库存上限、进攻 / 后勤预留、既有排队数量扣除；草案发布再次检查规则、归属、共享库存、在途和实际排队寿命。

陨石任务保留原生安全报价数量，通过现有 dispatchExpansion 限速执行，不在出队重新报价。队列中的陨石在全局合并时保留；停止、恢复或配置变更取消未完成草案，迟到结果不得重新入队。目标报告最多保存 128 条，显示最近 6 条；已消失目标随检查清理。GameWorld.bodyQuoteIssue 读取同一份原生报价解释拒绝原因；PlanningQuotes 连同失败报价缓存原因，不为展示诊断额外查询服务器。实际出队失败由 specialTargetSkipReason 和执行预算核验给出日志。

PlanningQuotes 先索引快照行，再按访问惰性生成依赖指纹。全局规则仍保守失效所有报价；来源覆盖变化仅使该来源缓存和 CandidateSearch 游标失效。全局草案在分配前过滤规则变化的候选，发布时再次核验每项计划，保留不受影响的队列。后勤航路也用来源规则指纹，发布补给草案重新检查最终占领目标锁；进攻同步完成释放屏障时唤醒前线与陨石检查。

模拟测试覆盖 4,000 来源下每目标每批最多 4 次报价且轮转不饥饿、保留全部搜索范围、类型隔离、共享预算、排队过期、实际出队过期日志、全局草案挂起仍派出陨石、不重复发布、局部规则变化保留其他来源候选并启动倒计时，以及远处覆盖变化零新增报价。快速报价测试只访问 4,000 个来源中的一个时，仅序列化该来源一次。没有在真实账号中自动发射或升级来验证本版。


## v0.15.6 先比较抵达时间，再比较舰队数

rapid 模式的 better、每目标选项排序及大型规划的前 8 项裁剪，统一为占点数、总 completionMs、舰队数、收益与数量顺序。同样任务数下批量派兵各占一个时隙，因此排队时间之和相同；比较 completionMs 总和可比较总占领耗时。completionMs 使用所有参与来源中的最大航时，不能使用 lead 的航时冒充占领时间。旧省略 maxTravelMs 的截止时间接口保留其原比较行为。

FrontierPlanner 不在得到可行单星报价时停止比较。候选来源索引围绕目标查找，取最近 10 颗及最强 10 颗去重；可生成不包含最初大兵源的合兵。已可单星占领的锚点参与合兵不会更快，替代来源的攻击上界不足时不额外报价；等于或慢于现有单星的路线不加入替代方案。其余沿用 coalitionOptions 的损耗、范围、两两距离、抵达时差和分配校验，最多 4 个协同目标与整批 96 次评估，未添加出队重报价。按 completionMs 排序快速结果，提交后由现有类型目标锁排除迟到全局草案里的重复方案。

新增回归覆盖：783 驻军、附近 464+396 与远处单星比较；精确和超过 1,000 候选的裁剪路径；同抵达时间优先少舰队、最晚支援决定占领时间、不能为速度减少可占点数；附近损耗导致不足时保留单星；全局草案暂停时快速合兵先通过原生批量接口发射，草案恢复后不重复远程派兵。测试使用模拟原生航路，未将截图里的邻近星球实际预算与航路视为已验证。

## 安稳发育模式

在「自动扩张」设置中选择「安稳发育：挂机占陨石」，手动启动后持续扫描并占领可及时抵达的无主陨石，暂缓孤立暴露目标。停止后才能切换模式；旧设置默认仍为自动扩张，切换不会覆盖原有的恒星、陨石或扩张取向偏好。

安稳发育复用扩张的独立队列、防守预算、固定战区、后台执行及断线恢复，关闭行星候选、前线检查和行星 / 恒星集结，不占行星或恒星。无陨石时持续等待；陨石检查计入排队、航程及到期安全余量。可继续使用「按收益与占领时间升级」，遵守连续稳定、无邻敌 / 来袭、无附近无主陨石机会和回本周期限制；未选择的行星 / 恒星目标不阻止升级。进攻仍独立控制，和平挂机时需自行停止进攻。刷新后不会自动启动。
