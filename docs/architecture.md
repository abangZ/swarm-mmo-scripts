# 架构与开发约定

当前 v0.11.0，React 19、TypeScript、esbuild、pnpm。发布物为包含 React、React DOM、业务代码与 Shadow DOM 样式的单个 IIFE 油猴脚本。

## 职责划分

| 目录 / 文件 | 职责 |
| --- | --- |
| `src/main.ts` / `app/mount.tsx` | 去重挂载、页面缓存恢复、React root 与卸载清理 |
| `app/controller.ts` | 唯一 Commander、两个模式的状态/设置、日志、只读战区预览 |
| `app/settings.ts` / `app/regions.ts` | 旧参数兼容、秒/毫秒转换、独立战区与敌人偏好持久化 |
| `ui/AutomationPanel.tsx` | 共用运行面板；扩张保留合兵设置，进攻只显示单星参数 |
| `ui/RegionSettings.tsx` | 地图中心/选中星球取点、区域概览、敌人筛选与定位 |
| `game/session.ts` / `game/map-selection.ts` | 地图与连接发现、只读取点/地图定位；React Fiber 只出现在 session 层 |
| `game/expansion-world.ts` | 统一世界适配器：订阅、库存、联盟、原生自动化、舰队、报价、原生发射 |
| `features/commander/` | 固定区域规则、动态防守预算、共享扫描/账本和两条独立执行队列的生命周期 |
| `features/attack/planner.ts` | 指定敌人筛选、单星攻击余量、可执行/短期攒兵方案 |

| `features/attack/rally.ts` | 大规模己方集结、据点推进、补给需求和批次复核 |
| `features/expansion/proposals.ts` | 混合候选、在途缺口、无主星单星/合兵提案与执行复核 |

## 共享预算、独立队列

每个挂载只有一个 Commander 与一个执行用 GameWorld。扩张/进攻各有配置、running、queue、计数；共用跨标签页操作锁、扫描、已发射扣款和在途目标记录。协调器为每个模式维护一个异步任务和取消信号，分别规划、等待间隔、发射和同步；扩张的分片规划及回执等待不阻塞进攻。每条队列内部最多一个任务。

预算：库存减去防守预留和未同步扣款。防守预留在重叠区域取更严格的固定下限/前线比例，再加已知敌方来袭的最大攻击上界。原生自动升级/转发来源排除。进攻的具体任务预留或有期限的攒兵计划再从扩张预算中扣除。发射准备在同一个同步步骤中预扣来源兵力、标记待同步来源和目标，另一队列出队时重新检查共享账本与最新进攻预留。攒兵最多 120 秒，超时冷却 60 秒，停止进攻立即释放。

`reserveFor` 对已知敌方舰队按 arrival 排序，每个前缀计算 `2 × 累计来袭兵力 + 2 − floor(max(0, ETA − 60 秒) / 60 秒) × level`，取各前缀与零的最大值，再加固定 / 前线守军。产兵只使用合法等级 1～10 的最低基础产量，保留一个完整生产周期的时间缓冲，不计科技、未来友军或盟友补给；缺失等级按零产量处理，缺失或非法来袭数量 / 时刻按不可出兵处理。逐前缀约束避免用最后一批抵达前的生产替第一批防守。

跨标签页 Web Lock 仍覆盖整个 Commander 会话，不由两个模式分别抢锁。扩张间隔保留配置的 1～2 秒，进攻在控制器和 Commander 两层固定为 1 秒；覆盖扫描周期仍取最小值。runtime 的 `dispatch` 按模式维护独立的执行状态和 localStorage 时间戳，以实际发射为基准，确认和库存同步耗时计入各自间隔；同步完成后即可准备本队列的下一个计划。各队列内部串行完成，不补发错过的定时操作；取消信号可立即终止未发射的间隔等待，不消耗发射间隔。

增加/停止模式会递增配置 revision，使正在分片计算或等待限速的旧方案失效，并在新的联合扫描完成后恢复调度。执行闭包再次读取真实库存、敌我关系、目标与在途状态。覆盖扫描进行中或 coveredRevision 未追上配置 revision 时不允许发射。目标变化、任何来源丢失或库存不足均取消未发射任务。inventoryRevision 记录并行发射和同步；扩张算出空计划时，若期间库存版本变化则立即重新评估，避免对已经释放的来源再空等一秒。

进攻在 `OffensivePlanner.fork()` 副本上经 `runPlanning` 执行直攻和各据点的生成器。分片恢复同时校验配置 / 库存版本、运行状态与订阅；只有完整且仍有效的结果才替换主规划器和预留。并行发射、同步、占领确认和预留变化都会使库存版本变化，过期草案不能覆盖新据点状态。进攻首次成功扫描调用 `attackStartupIssue`，无来源 / 全部原生自动化时删除进攻配置并发布明确错误，下一轮重新确认扩张覆盖，不全局 fail。

停止一个模式保持另一个模式运行；停止期间的确认完成前，不允许该模式重启。已发射的兵力和目标锁仍属于全局账本，不能因为停止某个 Tab 而清除。全部停止后取消未发射任务，等待两条队列的已发请求及库存同步全部完成，再释放操作锁和世界订阅。即使一个队列失败，另一个已发请求也必须完成这段清理。

## 情报与策略边界

固定区域约束来源和目标，中心与半径以启动时的配置快照为准。进攻必须指定区域；扩张可选择全部领地以兼容旧行为。区域订阅包含警戒和科技覆盖缓冲带；不围绕区域外大量己方资产扩张空间订阅。

订阅内容包括己方星球与舰队、区域星球、所有飞向区域的舰队、附近恒星/基地、联盟与科技、己方原生自动化，以及区域玩家名字。先等待订阅确认才计算，失败整体停止。区域预览使用独立的短期只读 World，不获取操作锁、不派兵；编辑区域或卸载时旧响应失效，最终释放订阅。

`GameWorld` 按查询字符串保存长期订阅，通过 `subscriptionBatches` 保留既有网格和玩家 ID 分组，每组最多 24 项；删除不再需要的项，新增项先填已有分组空位，再建新组。完整分组保持查询不变，增长只影响尾组/空位，不全局重新排序分块。批次总数受历史覆盖规模上界约束，不随扫描次数增长。复用相同的活跃句柄，只增补缺失查询、释放不再需要的查询。只有扫描成功才发布新分组；扫描取消只回收本轮新建句柄，已持有句柄和原分组留到下一轮或最终清理；失效订阅或断线仍停止。`needsScan` 检出战区内新增来源时提前补覆盖，全领地模式也无需等待扫描周期。`read` 和每次计算分片恢复时的 `refreshQuotes` 校验连接、订阅并清空原生报价缓存，`quote` / `route` 仅在同一个同步片段内复用结果，出队重新 `read`。分片只保留候选规划数据，不把旧报价用于实际发射。

敌方星球只使用单星原生报价，追加生产时点误差与占领守军，并按航行损耗转换；有其他舰队在途则跳过。尚未实现直接多波攻敌、跨战区追击或恒星/基地战斗。不把公开前端报价当成完整的服务器战斗模拟。

无主星允许 2～3 来源 native bulk。安全余量统一为 `captureMargin = 1`，单星报价与合兵抵达需求均使用此常量。已存在外部己方舰队时，仅在同星系到达兵力、时间和归属均可证明时按缺口补兵；未知损耗、其他玩家竞争或已有助手目标锁继续等待。

发射前记录来源扣款，并将涉及来源加入 pendingSources；在确认与库存同步期间，两队列均不再使用这些来源，周期扫描也不能提前清除它们的扣款，其他来源可并行派兵。确认成功后记录在途任务，再调用 `syncInventory` 对涉及来源按最多 24 个 ID 短期订阅。收到新订阅确认后仅释放这些来源的扣款，保留原有长期订阅和在途锁，避免从已更新库存重复减去同笔发射。同步失败保留已确认的发射事实并停止，不打未知发射标记、不重试。停止期间等同步清理完成再释放世界；旧模拟适配器无此方法时保留完整扫描后释放的兼容行为。

占领归属在扫描中核对，发射成功不计占领。未看到舰队且没有占领时，至少等待预计抵达时间加 5 秒才记为未确认占领并释放目标锁。断线/身份变化停止；未知发射结果使两个模式都停止，明确核对解锁后仍需手动重启。持久化未知标记为每模式 token 的记录；本进程 activeRequests 中的待确认请求允许另一队列正常运行，刷新后失去该集合则所有遗留 token 都按未知处理。旧版单 token 仍阻止启动。每条迟到成功回执只清除自己的 token，不能覆盖另一队列的失败标记。

## 大规模己方集结

`OffensivePlanner` 持有 1～3 个独立 `RallyPlanner` 据点（默认 3，指定 rallyId 时为 1），各自保存集结目标、期限与前移状态。目标战斗依旧是单星；大规模来源只向己方中转星增援。固定战区约束所有来源、中转星和敌方目标。

每轮先让 `attackPlanSteps` 对全部来源生成直攻候选，复用有界分配器求多目标计划，再将每个直攻的数量从预算扣除，剩余预算依次交给各据点。通过 usedHubs / excluded 排除重复据点和已安排目标，各据点只预留具体数量。`rallyId` 不限制直攻来源。`OffensivePlan.jobs` 交替放入直攻和补给，补给按上次实际执行据点轮转；合并队列仍受 horizonMs / 1 秒的容量限制，被补给挤出窗口的直攻释放预留。补给预计排队按据点数以及直攻交替保守计入，不为扩张占用时隙乘以 2。

自动选址对所有候选据点分片检查到敌方的可行航路，再混合最快 4 个和库存最多 4 个据点，各自比较最多 3 个目标的完整募集方案；比较集结等待加进攻航行的总抵达时间，再比较所需兵力。有已知敌方来袭的据点不参与。不可行 / 超时路线不会在按库存截取时挤掉前沿据点；使用集结或混合队列时不宣称全局精确最优。

每轮填充空闲 / 前移据点之前，先读取所有仍有效 campaign 的据点和目标占用，再把其他 campaign 的占用传入本据点的候选排除集合，避免较早的规划槽抢走后续已筹兵任务。这不排除直攻，也不锁定补给来源的剩余兵力；据点失去归属、离开战区、启用原生自动化、目标失效或任务过期时不保留占用。

`Assignment.kind = reinforce` 区分补给与占领。单个补给批次最多 50 个来源，不经过扩张规划器的 3 来源约束；集结计划混合最多 1,000 来源，为全部待用贡献预留具体库存。批次只占一次进攻队列操作，停止或失效时不拆成单支重试。同一个来源的未预留余量可以继续用于其他任务。

集结需求计入等待期间的敌方生产、敌方报价/保守上界、各段损耗、队列时间，以及中转星的动态留兵比例和已有守军缺口。当前在途与本地确认记录合并去重；本地按每支补给的预计到达时间记录，不将已经到期的承诺再加到实际库存。这些预测只决定募集量，实际出击必须由真实已到账库存通过最新报价检查。

集结补给单独记录，不能加入占领目标锁并把己方中转误计为 captured。新的订阅确认与到达缓冲清理补给跟踪。`launched` 只清除同目标的集结任务；独立直攻不清除另一个集结。记录需要前移的主攻目标，只有其后续占领确认才触发对应据点前移，不影响其他据点；独立直攻占点不打断活动集结。前移不重写战区中心，用户可关闭。中转有敌军来袭、丢失归属、启用原生自动化或已足够出击时，取消排队中的旧补给批次。

`rallyId` 以十进制字符串持久化，再转换 bigint；`rallyMinutes` 单独控制补给航行，默认 30 分钟；旧表单补入 rallyHubs = 3，不改变已存区域 / 敌人。阶段状态展示每个中转与敌方目标、实际可用库存、预计需求和在途补给。短期自然攒兵与大规模集结是不同策略：前者最多 120 秒，后者有最长补给航行 + 进攻最长航行 + 队列窗口 + 60 秒的期限。

## 候选与性能

每颗来源最多 n 个混合候选，锁定/不可补兵目标在截取前排除。候选报价先在 max(32, 8n) 个混合样本内检查航程和预算；评估至少 2n 个且已找到 n 个可行单星候选时提前结束。优先用可行单星补足候选，剩余槽位供合兵候选使用，避免不可用邻居堵住后方来源；预算为零的来源不查询报价。

`bestCandidates` 用稳定最大堆保留距离排序的前 `max(32, 8n)` 项；驻军、单位产量和附近机会三种与来源无关的排序只对可达目标并集计算一次，再按各来源距离过滤。`PlanetIndex.ordered` 保留与 `near` 相同的网格和插入顺序，确保平局与完整逐来源排序相同。附近机会预计算也设置分片点。仍遍历全部来源、完整邻域，不减少 n、搜索距离或可行目标补位数量。距离排名及空间范围筛选使用距离平方。

`expansionProposalSteps` / `expansionPlanSteps` 和进攻规划均使用生成器；原同步函数仅供算法测试与同步调用。Commander 通过 `runPlanning` 每约 8ms 用计时器让出主线程；来源、报价小批次、合兵目标、据点、补给来源和分配搜索均有检查点。这是协作调度预算，不是每个片段的硬耗时保证。每次恢复检查配置 revision、运行状态与页面可见性，旧计算取消后关闭生成器；报价阶段恢复还须校验连接/订阅。两条队列使用同一份共享库存、进攻预留与在途锁，不能各自分配完整库存。

两种模式均将 `maxTravelMs`（默认 30 分钟）作为独立航程上限；`horizonMs` 仅限制队列预计发出时间。`planExpansion` 第五个参数启用此语义：占点数、舰队数之后先比较总航时，再比较收益与成本，并按短航程先发。省略第五个参数时仅保留旧调用者的截止时间 / 收益优先语义，当前运行模式均显式传入上限。保留能增加占点数的合兵方案；相同占点数时优先单星，避免平局时不必要的拆兵。合兵最多 6 颗候选再枚举，出队时可改成新近可行的单星，但要先扣除其他队列目标所需预算。

小规模搜索最多 20,000 节点；大规模裁剪为最多 128 个目标、每目标 8 个方案，界面明确显示有界优化。不是全地图或未来多步战略最优。空闲时约每秒从活动订阅重新评估；有任务则在发射确认及库存同步后开始下一轮，新增来源提前触发覆盖扫描。提案同时返回各来源可用预算与阻塞原因，Commander 汇总已分配来源并保留最多 6 颗未分配来源供 UI 查看，不将这些诊断当作兵力预留。

## React 生命周期和显示

React 通过 `useSyncExternalStore` 订阅控制器。切换 Tab、收起/展开不会创建新调度器。两个模式的设置分别折叠；收起状态同时显示两个运行状态和最近日志，运行日志每模式最多 50 条、总量最多 100 条，活动模式不冲掉停止模式的诊断。进攻停止且 error 时自动展开其设置。日志条目不可变，行组件通过 React memo 复用已显示记录，避免每次状态更新重建全部日志；时钟格式器复用同一个 Intl.DateTimeFormat。

`app/version.ts` 从 `package.json` 引入版本，esbuild 内联到运行包。版本位于滚动面板和收起按钮之外，始终可见；不读取本地加载器的元数据。

两个 Tab 即使隐藏也会渲染，所有表单、状态、日志 ID 必须唯一。倒计时仅更新界面，不扫描或派兵；根节点卸载时清理计时器。`pagehide` 停止控制器，`pageshow.persisted` 恢复一个未启动面板，保留未知结果标记。React 渲染错误也停止控制器。

扩张参数沿用 `swarm-helper-expansion-settings`；进攻用 `swarm-helper-attack-settings`；区域与敌人用 `swarm-helper-regions-v1`。旧配置补入默认 `maxTravelMs`，保留原有搜索距离和规划窗口；扩张 UI 明确分开这两个时间参数。旧进攻 intervalMs 无论原值都归一为 1 秒，UI 不提供修改入口；扩张间隔不变。不持久化运行状态，星球 ID 始终使用 bigint，玩家 identity 使用完整字符串。
