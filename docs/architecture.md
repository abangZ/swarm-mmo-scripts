# 架构与开发约定

当前 v0.8.0，React 19、TypeScript、esbuild、pnpm。发布物为包含 React、React DOM、业务代码与 Shadow DOM 样式的单个 IIFE 油猴脚本。

## 职责划分

| 目录 / 文件 | 职责 |
| --- | --- |
| `src/main.ts` / `app/mount.tsx` | 去重挂载、页面缓存恢复、React root 与卸载清理 |
| `app/controller.ts` | 唯一 Commander、两个模式的状态/设置、日志、只读战区预览 |
| `app/settings.ts` / `app/regions.ts` | 旧参数兼容、秒/毫秒转换、独立战区与敌人偏好持久化 |
| `ui/AutomationPanel.tsx` | 共用运行面板；扩张保留合兵设置，进攻只显示单星参数 |
| `ui/RegionSettings.tsx` | 地图中心/选中星球取点、区域概览、敌人筛选与定位 |
| `game/session.ts` / `game/map-selection.ts` | 地图与连接发现、只读取点/地图定位；React Fiber 只出现在 session 层 |
| `game/expansion-world.ts` | 统一世界适配器：订阅、库存、联盟、原生自动化、舰队、报价、原生发射 |
| `features/commander/` | 固定区域规则、动态防守预算、两个模式共用的扫描与串行执行生命周期 |
| `features/attack/planner.ts` | 指定敌人筛选、单星攻击余量、可执行/短期攒兵方案 |
| `features/attack/rally.ts` | 大规模己方集结、据点推进、补给需求和批次复核 |
| `features/expansion/proposals.ts` | 混合候选、在途缺口、无主星单星/合兵提案与执行复核 |
| `features/expansion/planner.ts` / `cooperation.ts` | 有界分配、截止时间、多来源损耗与库存约束 |
| `features/expansion/engine.ts` | 旧单模式入口的兼容 facade，委托同一个 Commander 实现，无第二套调度 |
| `runtime/operations.ts` | 跨标签页 Web Lock、操作间隔、未知结果锁定 |
| `shared/planet-index.ts` | 32 单位空间索引，避免每颗来源遍历整个帝国 |

算法不依赖 React。组件只通过 props 调用控制器，不直接订阅游戏或调用 reducer。World 接口可注入模拟实现，真实适配器始终要求新情报表可用；旧测试适配器仍支持无动态情报的扩张兼容入口，进攻则必须显式具备完整情报。

## 并行模式、串行操作

每个挂载只有一个 Commander 与一个执行用 GameWorld。扩张/进攻各有配置、running、queue、计数；共用跨标签页操作锁、扫描、已发射扣款和在途目标记录。两个规划器顺序读取同一快照，分配同一预算，并且每轮只执行一个任务。

预算：库存减去防守预留和未同步扣款。防守预留在重叠区域取更严格的固定下限/前线比例，再加已知敌方来袭的最大攻击上界。原生自动升级/转发来源排除。进攻的下一项任务或有期限的攒兵计划再从扩张预算中扣除；双方均有工作时轮流服务。攒兵最多 120 秒，超时冷却 60 秒，停止进攻立即释放。

跨标签页 Web Lock 仍覆盖整个 Commander 会话，不由两个模式分别抢锁。全局操作间隔取激活模式中的最大值，覆盖扫描周期取最小值。`nextDispatch` 以实际调用发射接口的时刻为基准，确认和库存同步耗时计入间隔；仍等待完成才执行下一次，不补发错过的定时操作。取消准备不消耗发射间隔，跨标签页限速始终由 runtime 检查。

增加/停止模式会递增配置 revision，使等待限速的旧方案失效，并在新的联合扫描完成后恢复调度。执行闭包再次读取真实库存、敌我关系、目标与在途状态。目标变化、任何来源丢失或库存不足均取消未发射任务。

停止一个模式保持另一个模式运行；停止期间的确认完成前，不允许该模式重启。已发射的兵力和目标锁仍属于全局账本，不能因为停止某个 Tab 而清除。全部停止后释放世界订阅；未确认请求仍持有锁直到确认/超时。

## 情报与策略边界

固定区域约束来源和目标，中心与半径以启动时的配置快照为准。进攻必须指定区域；扩张可选择全部领地以兼容旧行为。区域订阅包含警戒和科技覆盖缓冲带；不围绕区域外大量己方资产扩张空间订阅。

订阅内容包括己方星球与舰队、区域星球、所有飞向区域的舰队、附近恒星/基地、联盟与科技、己方原生自动化，以及区域玩家名字。先等待订阅确认才计算，失败整体停止。区域预览使用独立的短期只读 World，不获取操作锁、不派兵；编辑区域或卸载时旧响应失效，最终释放订阅。

`GameWorld` 按查询字符串保存长期订阅，扫描时稳定排序网格和玩家 ID，复用相同的活跃句柄，只增补缺失查询、释放不再需要的查询。扫描取消只回收本轮新建句柄，已持有句柄留到最终清理；失效订阅或断线仍停止。`needsScan` 检出战区内新增来源时提前补覆盖，全领地模式也无需等待扫描周期。`read` 清空原生报价缓存，`quote` / `route` 在同一个同步快照内复用结果，出队重新 `read`，不复用旧轮次报价。

敌方星球只使用单星原生报价，追加生产时点误差与占领守军，并按航行损耗转换；有其他舰队在途则跳过。尚未实现直接多波攻敌、跨战区追击或恒星/基地战斗。不把公开前端报价当成完整的服务器战斗模拟。

无主星允许 2～3 来源 native bulk。安全余量统一为 `captureMargin = 1`，单星报价与合兵抵达需求均使用此常量。已存在外部己方舰队时，仅在同星系到达兵力、时间和归属均可证明时按缺口补兵；未知损耗、其他玩家竞争或已有助手目标锁继续等待。

成功发射后先记录来源扣款和在途任务，再调用 `syncInventory` 对涉及来源按最多 24 个 ID 短期订阅。收到新订阅确认后仅释放这些来源的扣款，保留原有长期订阅和在途锁，避免从已更新库存重复减去同笔发射。同步失败保留已确认的发射事实并停止，不打未知发射标记、不重试。停止期间等同步清理完成再释放世界；旧模拟适配器无此方法时保留完整扫描后释放的兼容行为。

占领归属在扫描中核对，发射成功不计占领。未看到舰队且没有占领时，至少等待预计抵达时间加 5 秒才记为未确认占领并释放目标锁。断线/身份变化停止；未知发射结果使两个模式都停止，明确核对解锁后仍需手动重启。

## 大规模己方集结

`OffensivePlanner` 持有当前集结目标与可前移的中转星。目标战斗依旧是单星；大规模来源只向己方中转星增援。固定战区约束所有来源、中转星和敌方目标。

每轮先让 `planAttack` 对全部来源生成直攻候选，复用有界分配器求多目标计划，再将每个直攻的数量从预算扣除，剩余预算交给集结规划。`rallyId` 不限制直攻来源；直攻目标也从集结候选中排除。`OffensivePlan.jobs` 同时保留直攻和补给，`next` 根据上一次实际执行的种类交替选择。外层 Commander 再与扩张轮流调度，规划时将共享队列时隙计入航行预测。

`Assignment.kind = reinforce` 区分补给与占领。单个补给批次最多 50 个来源，不经过扩张规划器的 3 来源约束；集结计划混合最多 1,000 来源，为全部待用贡献预留具体库存。批次仍只占一次共享队列操作，停止或失效时不拆成单支重试。同一个来源的未预留余量可以继续用于其他任务。

集结需求计入等待期间的敌方生产、敌方报价/保守上界、各段损耗、队列时间，以及中转星的动态留兵比例和已有守军缺口。当前在途与本地确认记录合并去重；本地按每支补给的预计到达时间记录，不将已经到期的承诺再加到实际库存。这些预测只决定募集量，实际出击必须由真实已到账库存通过最新报价检查。

集结补给单独记录，不能加入占领目标锁并把己方中转误计为 captured。新的订阅确认与到达缓冲清理补给跟踪。`launched` 只清除同目标的集结任务；独立直攻不清除另一个集结。记录需要前移的主攻目标，只有其后续占领确认才触发据点前移；独立直攻占点不打断活动集结。前移不重写战区中心，用户可关闭。中转有敌军来袭、丢失归属、启用原生自动化或已足够出击时，取消排队中的旧补给批次。

`rallyId` 以十进制字符串持久化，再转换 bigint；`rallyMinutes` 单独控制补给航行，默认 30 分钟。阶段状态展示当前中转与敌方目标、实际可用库存、预计需求和在途补给。短期自然攒兵与大规模集结是不同策略：前者最多 120 秒，后者有最长补给航行 + 进攻范围 + 60 秒的期限。

## 候选与性能

每颗来源最多 n 个混合候选，锁定/不可补兵目标在截取前排除。候选报价先在 max(32, 8n) 个混合样本内检查航程和预算；评估至少 2n 个且已找到 n 个可行单星候选时提前结束。优先用可行单星补足候选，剩余槽位供合兵候选使用，避免不可用邻居堵住后方来源；预算为零的来源不查询报价。

扩张将 `maxTravelMs`（默认 30 分钟）作为独立航程上限；`horizonMs` 仅限制队列预计发出时间。`planExpansion` 第五个参数启用此语义：占点数、舰队数之后先比较总航时，再比较收益与成本，并按短航程先发。省略第五个参数时保留进攻的原截止时间 / 收益优先语义。保留能增加占点数的合兵方案；相同占点数时优先单星，避免平局时不必要的拆兵。合兵最多 6 颗候选再枚举，出队时可改成新近可行的单星，但要先扣除其他队列目标所需预算。

小规模搜索最多 20,000 节点；大规模裁剪为最多 128 个目标、每目标 8 个方案，界面明确显示有界优化。不是全地图或未来多步战略最优。每秒从活动订阅局部重新评估；新增来源提前触发覆盖扫描。提案同时返回各来源可用预算与阻塞原因，Commander 汇总已分配来源并保留最多 6 颗未分配来源供 UI 查看，不将这些诊断当作兵力预留。

## React 生命周期和显示

React 通过 `useSyncExternalStore` 订阅控制器。切换 Tab、收起/展开不会创建新调度器。两个模式的设置分别折叠；收起状态同时显示两个运行状态和最近日志，运行日志按模式筛选，总量最多 100 条。

`app/version.ts` 从 `package.json` 引入版本，esbuild 内联到运行包。版本位于滚动面板和收起按钮之外，始终可见；不读取本地加载器的元数据。

两个 Tab 即使隐藏也会渲染，所有表单、状态、日志 ID 必须唯一。倒计时仅更新界面，不扫描或派兵；根节点卸载时清理计时器。`pagehide` 停止控制器，`pageshow.persisted` 恢复一个未启动面板，保留未知结果标记。React 渲染错误也停止控制器。

扩张参数沿用 `swarm-helper-expansion-settings`；进攻用 `swarm-helper-attack-settings`；区域与敌人用 `swarm-helper-regions-v1`。旧配置补入默认 `maxTravelMs`，保留原有搜索距离和规划窗口；扩张 UI 明确分开这两个时间参数。不持久化运行状态，星球 ID 始终使用 bigint，玩家 identity 使用完整字符串。

## 验证

运行 `pnpm typecheck`、`pnpm test`、`pnpm build`。测试入口自动发现 `tests/*.test.ts(x)`，临时编译后用 Node test runner 执行，并清理临时目录。

- `strategy.test.ts`：区域边界、动态守军、盟友/敌人过滤、跨星系余量、在途缺口、有界规划与配置兼容。
- `rally.test.ts`：数百来源募集、50 来源批次、到账前禁止攻敌、守军缺口、批次失效、据点前移和来源跨任务复用。
- `commander.test.ts`：异地同时运行、重叠预算、攒兵释放、公平调度、停止单模式、排队失效、未知结果全停。
- `game.test.ts`：地图控制器、区域/舰队/科技订阅、玩家目录、批量发射与订阅清理。
- `expansion.test.ts` / `planner.test.ts`：保留无主星单星/合兵、库存、时间与停止回归。
- `expansion-speed.test.ts`：64 距离 / 120 秒规划下五颗后方来源参与、短程优先、可行候选补位、发射间隔计时、新来源提前扫描、旧参数迁移和候选报价工作量上限。
- `world-subscriptions.test.ts`：稳定范围无重复订阅、扫描取消与新覆盖、快照报价缓存、订阅失效停止。
- `ui.test.tsx` / `controller.test.ts` / `page-lifecycle.test.ts`：React act、唯一 ID、选区和选敌人、异步预览失效、卸载与页面恢复。
- `operations.test.ts`：跨实例互斥、限速、未知结果与明确解锁。

浏览器检查使用本地模拟页面；真实游戏只做只读接口核对，不为了验证代码操作真实账号。静态接口核对与模拟通过不代表服务端已实际执行进攻。
